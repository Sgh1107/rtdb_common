## 6. 性能实测记录（bench_net）

### 6.1 用法

```powershell
cd build\Release
.\bench_net.exe                       # 默认 rows=200000 batch=512（进程内 rtdbd）
.\bench_net.exe --ci                  # CI 口径：rows=50000 + 阈值断言（ctest 自动跑）
.\bench_net.exe --host 127.0.0.1 --port 5599 --user demo --password demo123 --salt demo-salt
```

口径：同键覆盖写（版本数组仅 row_ver 就地更新，无 var 池增长）；键位预算
`2×batch+样本+32 ≤ row_cap`；块阶段与 ops 阶段键区间分离（ops 首轮 insert 后转
update 复用键）。

### 6.2 实测（Windows 11 / MSVC Release / loopback 同机，节选一次完整运行）

```
BENCHNET config rows=200000 ops_rows=40000 batch=512 table=bench_net mode=inproc
BENCHNET block rows_per_sec=211558 req_per_sec=413 rows=199680 secs=0.9439
BENCHNET ops rows_per_sec=194884 req_per_sec=381 rows=39936 secs=0.2049
BENCHNET ping_us p50=23.3 p99=43.1 max=87.7 (n=200)
BENCHNET write1_us p50=23.6 p99=125.9 max=1654.6 (n=200)
BENCHNET sub_us p50=82.6 p99=133.7 max=141.4 (n=100)
BENCHNET scan rows=1324 secs=0.0013 rows_per_sec=1003639

```

（`frame_errors=2` = 进程内服务端收尾时客户端主动关闭产生的 EOF，非协议错误。）

CI 门禁口径（`--ci`，50k 行）：实测块阶段 209,437 行/s、阈值
`rows_per_sec≥50000`、`P99≤5000µs`，`BENCHNET RESULT PASS`；检测到
`ASAN_OPTIONS/TSAN_OPTIONS/UBSAN_OPTIONS/MSAN_OPTIONS` 任一存在时自动放宽为
5k 行/s、100ms（消毒插桩下吞吐/延迟失真，仅保活性与正确性）；Debug 构建
（覆盖率作业/本地 gcov 测试经 CMake `$<CONFIG:Debug>` 传 `--relaxed`）同
口径放宽（-O0 性能不具参考性）。

### 6.3 批行数上限的两个来源（排障口径）

1. **建表 `row_cap`**：行数据区 64KB（`schema.hpp` 闸门）；3×int64 + null 位图
   经 `PlanRowLayout` 得 `rec_fixed_len=32`（含对齐）→ 上限恰为 **2048**（2730
   建表即 306 `kLimitExceeded`）。
2. **单批行数**：WAL 记录区 64KB/批；3×int64 表 **512 行安全、768 行即 306**
   （kLimitExceeded，"configured limit exceeded"）。故 bench 默认 batch=512。

## 7. 混沌与恢复实测记录

### 7.1 用例与驱动

```powershell
cd build\Release
.\rtdb_unit_tests.exe --gtest_filter="NetChaos.*"   # 双场景，约 9s
# 驱动脚本（Windows 用 Git Bash；Linux 直接执行）
bash scripts/chaos_m3.sh 20                         # ×20 轮 ≈3 分钟，日志留档
```

| 场景 | 做法 | 终检 |
|---|---|---|
| `Kill9RestartResumesDelivery` | 每轮：写入 8 条 → 等交付 → 硬杀（TerminateProcess/SIGKILL，退出码 9/137）→ 同映像/同端口重启，共 3 轮 | 无缺漏 + 交付 seq 严格递增 + 写者心跳前进 + 状态回调（+4/−3） |
| `KillDuringWriteBurstSustainsDelivery` | 预置 64 键（应答并交付确认）→ 写线程持续 update（唯一 tag，2ms 节拍；写量按 64KB 环窗口预算封顶：acked 上限 120 = 40 条/轮 ×3 轮，`static_assert` 构造性保证全程 WAL 用量 < 64KB ⇒ 无回绕 ⇒ 无 402 溢出）→ 主线程写流中杀/重启 ×3 | **acked ⊆ 交付**（写类不自动重发 ⇒ 不得缺交付；允许重复） |

代表性一次运行（`--gtest_repeat=2` 两跑）：`attempts=123 acked=120 failed=3` /
`elapsed_ms=3754` / `elapsed_ms=3772`，交付 `unique_tags=186` / `186`（= 64 预置 +
120 acked + 至多 3 条"已提交但应答丢失"的额外交付，两跑均为 +2）。
`failed=3` 即每轮在飞中断一次。写量预算化原因：订阅窗口 = 64KB 环，Linux 真
2ms 节拍下未封顶的风暴写量会越过回收窗口 → 402 溢出后客户端整表重扫，历史
acked tag 按契约不可复原（docs/13 §8-W5 本轮修复记录）；故场景 2 按环窗口预算
封顶（构造性无回绕 ⇒ 无 402 溢出），终检强判据未放宽。语义依据：映像脏页由
OS 持有，进程终止不丢已提交数据（M1 混沌同结论），故"重启后无缺漏"为强断言。

### 7.2 平台活性判据加固（W5 暴露并修复的存量缺陷）

Windows `platform::IsSameLiveProcess` 原仅比对进程 CreationTime。进程被
TerminateProcess 终止后，其**进程对象在句柄/内核引用清零前仍可 OpenProcess**，
CreationTime 与存活进程一致 ⇒ 已死持有者被判"存活"，共享内存锁（ShmRootMutex）
死亡恢复在 5s 超时内无法接管——rtdbd 硬杀后 ~120ms 内重启 100% 复现
（`engine open: timeout`）。修复：GetProcessTimes 的 ExitTime 非零即视为已退出。
POSIX 对称加固：/proc 状态 `'Z'`（未回收僵尸）按死亡处理。修复后 120ms 间隔
重启 3 连全绿。

### 7.3 排空判据修正

`Subscription::position()`（最后交付事件 seq）与 `Ping().committed_seq`（最后已
提交记录 seq）**不可直接比齐**：批标记（BEGIN/COMMIT）不产生变更事件，末尾
position 可能稳定停在 `committed-1`。排空判据 = "交付集停增 + 泵在线"
（测试与 docs/04 §5 注记统一）。

## 8. 部署与安全边界

### 8.1 rtdbd 部署要素

```powershell
cd build\Release
# 口令摘要生成（每用户一条；盐为部署共享秘密）
.\rtdbd.exe --hash-password <口令> --salt <盐>
# 启动（默认仅回环 127.0.0.1:5599；显式 --listen 才对外）
.\rtdbd.exe --path data.rtdb --instance prod --listen 0.0.0.0:5599 `
    --auth-salt <盐> --user demo=<64HEX> [--exit-after-ms N]
```

关键默认（`src/server/config.hpp`）：`listen 127.0.0.1:5599`（安全默认）、
`initial_size_mb=256`、`session_ttl=30min`（滚动续期）、`max_sessions=64`、
`max_payload=4MiB`、`heartbeat=1s`、`max_delta=1MiB`、`delta_max_timeout=25s`。

### 8.2 双机演示（脚本或手工）

```bash
# A 机（服务端；脚本会把监听地址置为 0.0.0.0）
scripts/demo_two_hosts.sh server --port 5599 --rows 3 --write-ms 300
# B 机（客户端）
scripts/demo_two_hosts.sh client --host <A 机 IP> --port 5599 --seconds 30
```

手工等价命令（约定用户 `demo` / 口令 `demo123` / 盐 `demo-salt` / 表 `demo`，
与 `remote_demo` 默认一致）：

```powershell
cd build\bin\Release
.\remote_demo.exe --serve --listen 0.0.0.0:5599 --rows 3 --write-ms 300   # A 机
.\remote_demo.exe --host <A 机 IP> --port 5599 --seconds 30               # B 机
```

观察点：连接/认证 → `订阅就绪` → 逐条 `#N seq=… insert`（序严格递增）→ 录得
`已收变更 N 条`；服务端 Ctrl+C 强杀后重启可观察客户端退避重连与续传。

防火墙：Windows（管理员）`netsh advfirewall firewall add rule name="rtdb 5599"
dir=in action=allow protocol=TCP localport=5599`；Linux `sudo ufw allow 5599/tcp`。
跨机演示建议在受信内网执行，并在验证结束后关闭端口。

### 8.3 安全边界（明确告警）

- 协议为**明文 TCP + 摘要口令**（SHA-256(盐‖口令)），**不是 TLS**；仅限受信
  内网。公网暴露必须自行加隧道/网关（TLS 归 M4 评估）。
- rtdbd 默认只绑回环；对外监听须显式 `--listen`，并配合会话上限/防火墙。
- 盐与口令摘要按部署分发管理；轮换需重启 rtdbd 并同步客户端。
