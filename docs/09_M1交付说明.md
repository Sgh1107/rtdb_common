## 1. M1 目标回顾

| 项 | 内容 |
|---|---|
| 周期 | 约 6 周（W1~W6；规划 2026-08，本机收敛 2026-10-14） |
| 范围 | TableStore / Catalog / Index / WAL / 快照恢复（docs/05 §3） |
| 出口标准 | ① 崩溃注入（kill -9 × 随机点）后数据零丢失（per_second 档）；② CRUD 全链路单测绿 |
| 附加门禁（docs/08 §1） | engine/ 与 storage/ 行覆盖 ≥ 85%（全局 ≥ 80% 为 CI 现行强制）；内部 bench 量级确认（M1 不设门禁，基线随 M2 生效） |

M1 的定位是"引擎"：在 M0 的**多进程共享内存 + 跨进程锁 + 崩溃恢复 + 有序索引**地基上，
交付**表 / 目录 / 索引 / WAL / 快照恢复**这套可持久化存储引擎能力。引擎门面从 M0 的
"打开映像"扩展为完整闭环：

```
CreateTable(TableDef) / DropTable(name) / OpenTable(name)
Insert / GetByKey / UpdateByKey / DeleteByKey / ContainsKey   —— 单行 CRUD（主键寻址）
ExecuteBatch(span<BatchOp>)                                   —— 原子批量（组提交，一次落盘确认）
Scan(table, range) / ScanAll                                  —— 主键范围扫
AlterTableAddColumn(def)                                      —— 在线加列
CreateSecondaryIndex(def) / GetBySecondary(...)               —— 二级索引框架（非唯一 + 延迟重建开关）
```

### 3.2 测试基础设施三修复（W6 收尾，`98cd010`）

M1 后期本机全量验证暴露并修复的三个测试基建问题（均已复验）：

1. **ctest 并行竞争 → `RUN_SERIAL`**：各用例共享全局命名资源（映像文件路径 + Windows
   命名映射对象名，后者按内核对象名全局可见），并行下进程 A 的 TearDown 与进程 B 的
   SetUp/Open 偶发竞争（曾 3/113 间歇失败）。根因定位后全部用例置 `RUN_SERIAL TRUE`
   （`gtest_discover_tests` 与 `gtest_add_tests` 两条发现路径均覆盖），串行下零失败，
   `-j8` 三轮复验全绿；
2. **MinGW gcov 三坑 → 静态核心 + 静态发现 + manual dump**：① gcov 插桩 + MinGW DLL
   组合下，DLL 的覆盖率计数仅在卸载（detach）时转储，而插桩后的卸载/CRT 退出触发
   UCRT fast-fail(0xC0000409)，src/ 内核 .gcda 恒不产生（对照实验：build_gcc 无
   `--coverage` 时 10 个崩溃测试全过，定性为插桩与卸载的相互作用）；② `gtest_discover_tests`
   的 POST_BUILD 探测运行 `--gtest_list_tests`，gtest 在 `InitGoogleTest` 内部直接
   `exit()`，同样触发 fast-fail 令构建必败；③ `_Exit` 在 Windows 上仍经 ExitProcess
   卸载 DLL 无效。解法三合一：`RTDB_COVERAGE_STATIC_CORE=ON`（核心 STATIC 链入测试
   exe，单模块单 gcov 运行时）+ `RTDB_STATIC_TEST_DISCOVERY=ON` + main/CrashPoint 在
   gcov 构建下经 weak `__gcov_dump` 后 `_Exit`（普通构建 weak 为 null，零影响）；
3. **零告警清理**：`engine.cpp` ExecuteBatch 删死变量 `wal_ops_done`（gcc
   `-Wunused-but-set-variable`）；`test_main.cpp` 删死 lambda `now_us`；测试目标对
   gcc 增补 `-Wno-missing-field-initializers`（刻意部分聚合初始化，产品库不屏蔽）；
   `failpoint.cpp` 增 `[[noreturn]] HardExit`（MSVC C4715）。

另：`coverage_m1.py` 修正三方源码泄漏——gtest 源路径 `<build>/_deps/googletest-src/...`
   含 `/src/` 曾被误计入全局覆盖（虚低至 48.1%），按 `_deps/` 剔除后为真实值 95.9%。

| 指标 | 实测 | 基线（docs/05 §4） | 判定 |
