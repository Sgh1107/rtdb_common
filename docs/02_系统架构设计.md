# 02 系统架构设计

## 1. 分层总图

```
┌─────────────────────── 应用程序(任意第三方) ───────────────────────┐
│   嵌入式用法: 直接链接 librtdbcore            远程用法: 任意语言    │
├──────────────────────────────┬────────────────────────────────────┤
│  L4 访问接口层                │   网络客户端 rtdb_client           │
│   NativeApi(RAII句柄)         │   (TCP二进制协议/连接池/订阅游标)    │
│   CAbi(c导出稳定面)          │                                    │
├──────────────────────────────┴────────────────────────────────────┤
│  L3 引擎层                                                          │
│   Catalog元数据目录 │ Engine(CRUD/扫描/批量) │ IndexManager          │
│   ChangeLog │ Authz │ PerfCounters                                  │
├───────────────────────────────────────────────────────────────────┤
│  L2 存储层                                                          │
│   TableStore(柔性表头+定长记录区+变长池) │ WalGroupCommit │ Snapshot │
│   SharedBTree(共享内存B+树)                                         │
├───────────────────────────────────────────────────────────────────┤
│  L1 基础设施层                                                      │
│   ShmRegion │ IPC锁/信号量 │ Slab分配器 │ NSClock │ Logger │ ErrCode │
├───────────────────────────────────────────────────────────────────┤
│  L0 平台抽象 platform/(win32 / posix)                               │
└───────────────────────────────────────────────────────────────────┘

独立进程: rtdbd 守护进程 = L4网络服务端(L3引擎之上)
可选插件: rtdbsync-rdb(RDB同步适配器接口 IRdbSyncAdapter 的具体实现)
```

## 2. 两种部署形态（同一份数据）

```
【嵌入式】                          【服务端+远程】
App进程A   App进程B   App进程C        App进程D ──TCP──> rtdbd守护进程
    \         |         /                                        |
     \        v        v                                         v
      → 共享内存 "rtdb::<instance>" 数据区 ←──────────────────── 同一数据区
             (mmap 只读映射或经API写)
```
- **嵌入用法**：宿主链接动态库，mmap 打开同一命名共享内存段，通过引用/偏移直接操作 —— 走 L1-L4，无 socket；
- **远程用法**：只有 rtdbd 以读写方式打开数据区执行写入路径，远端仅能经 RPC —— 引擎保证单一写入入口时的锁竞争最小化。

**写入仲裁规则**（通用性关键决策）：默认允许多读者无限并发；写者按"实例角色"裁决——每个实例配置 `standalone | writer | reader` 角色，writer 职责可主备切换（ChangeLog 序号大的为主），从根源避免老系统备机 BAK 通道这类特例。

## 3. 共享内存整体布局

```
偏移0x00 ┌─────────────────────────────┐
         │ SuperBlock                  │  magic/version/layout_crc/机器字宽/时钟基准
         │ roles(writer_id等)          │  心跳时间戳、状态字
         ├─────────────────────────────┤
         │ MetaSection                 │  目录区: 表描述符数组(SchemaRecord)
         │  表名B+树 / ID B+树          │  两棵SharedBTree + 注册互斥锁
         ├─────────────────────────────┤
         │ WalRing                     │  组提交WAL环形缓冲(逻辑日志)
         ├─────────────────────────────┤
         │ TableDataSeg[]              │  每4KB一粒度slab分段
         │  表N: 定长记录区(cols偏移表) │  变长数据池(string/blob尾巴)
         │       记录版本号数组          │  DeleteBitMap(墓碑位图)
         ├─────────────────────────────┤
         │ IndexSeg[]                  │  各索引的SharedBTree根
         ├─────────────────────────────┤
         │ GlobalSeq & PerfCounters    │  全局递增seq、性能计数块
         └─────────────────────────────┘
```

要点：
1. **段(segment)+偏移寻址**：所有结构体之间只用 `uint64 offset` 互指，不存裸指针 → 跨 32/64 位安全、映像文件可搬家；
2. **每表三件套**：记录区（按当前 schema 的列偏移定长排列）+ 版本号数组 + 墓碑位图；变长列内容进池区，记录里存 `(pool_off,len)`；
3. **柔性 schema**：`SchemaRecord` 含 `col_count` 与列定义数组，物理布局带 `data_layout_ver`。加列=新列追加到记录尾扩展区并提供默认值填充位图，旧读者按自己的 layout 读 → 在线加列不重建；
4. **全局单调 seq**（int64）：任何提交成功的变更 `ChangeLog{seq, table_id, row_ver, op, ts}` 落 WAL 环；所有变化感知一律看 seq 游标，替代老系统的秒级时间戳（解决亚秒漏报缺陷）。

## 4. 并发控制设计

| 场景 | 机制 |
|---|---|
| 目录(建删改表) | 全局 `meta_rwmutex`（IPC 版 shared_mutex），低频 |
| 表级 | 每表一把 IPC `TableRWLock`（写独占）；读路径默认**免锁乐观读** |
| 行级乐观读 | 读者取行指针前读 `row_version` 快照 → 读完后重读比对，不一致则重试（版本号停止奇偶翻转判写中）；最多重试 N 次，超限降级走轻量行锁 |
| 写者组提交 | 写者拿表 X 锁 → 改内存 → 追加 WAL buffer → 按策略刷盘 → 更新 `committed_seq` → 发一次 IPC notify（订阅者被唤醒而非轮询） |

对比老系统收益：读完全不加锁达到老系统 S 锁效果；亚秒级变更不再漏报（seq 替代秒级时间戳）。

## 5. 变化传播（订阅）通道

```
订阅者: cursor = GetGlobalSeq()
循环: WaitForChange(timeout)  ←  IPC唤醒，非定时轮询
      拉取 (cursor, committed_seq] 区间的 ChangeLog → 应用过滤(表/列) → 回调
```
- 网络侧同样以游标差分传输增量（对齐老 rsrvd 发布-订阅意图，实现改为可靠游标流）；
- ChangeLog 环满时最早记录让位于快照重置点，订阅端支持"追赶失败→整表重取"语义。

## 6. 模块划分与依赖方向

```
platform/ ← infra/(shm,lock,log,clock,err) ← storage/(store,btree,wal,snapshot)
                                              ↑
                              engine/(catalog,index,changelog,authz,perf)
                                              ↑
                       api/(native_api,c_abi) ← server/(rpc,subscribe,session)
                                            ← client/(client_lib,pool,codec)
tools/: rtdbctl(CLI) / migrate_from_psrtdb / bench
```
依赖单向向下；engine 及以下**不得包含** server/client 任何符号（保证纯嵌入用户不被拖入网络栈）。
