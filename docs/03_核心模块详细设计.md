# 03 核心模块详细设计

> 命名空间统一 `rtdb`。所有跨进程结构体标注 `struct shm_` 前缀，禁止含虚函数/裸指针/std 容器。

## 1. platform/ —— 平台抽象（L0）
```
class SharedMemoryFile   // open(name, size, mode) / map() / close()，RAII
class IPCMutex           // 具名互斥: win SRWLOCK+事件 / posix unnamed sem in shm
class IPCEvent           // 具名通知: SetEvent/futex wake
class ThreadContext      // cpu亲和、优先级、命名
namespace fs             // 封装 std::filesystem 差异
```
关键决策：IPC 锁的**等待节点直接驻留共享内存**（老系统 SIMPLE_SX_LOCK 思路），支持异常进程死亡后的锁恢复：持有者写 heartbeat 时间戳，等待者超时未刷新则夺锁并标记 owner_dirty。

## 2. infra/ —— 基础设施（L1）

### 2.1 ShmRegion & ShmAllocator
- `ShmRegion`：SuperBlock 校验（magic/version/layout_crc），提供 `ptr(off)`。
- `SlabShmAllocator`：分级 slab（32B..64KB）+ 空闲链表；分配元数据自描述；`Allocate/Deallocate(uint64 off)`；表数据段按需扩段。
- `MVarLenPool`：变长列专用池（最佳适配 + 分裂合并），返回 `pool_off+len`。

### 2.2 SharedBTree（对标老 COFMBTree，重写为模板）
```
template<size_t MaxKeyLen, typename PayloadT>
class SharedBTree {          // 节点定长4KB，全部offset寻址
    int  Insert(k, v); int Remove(k); bool Find(k, v*) const;
    Cursor SeekRange(lo, lo_incl, hi, hi_incl);   // 前缀/范围扫描
};
using StringBTree = SharedBTree<64, uint64>;   // 名→table_id
using IntBTree    = SharedBTree<8,  uint64>;
// 复合键索引: key = concat(colN编码值...) 固定编码保证有序:
//   int → 大端8B; string → 补0截断; double→可排序序数变换; null→0x00前缀
```

### 2.3 Logger / NsClock / Error
- `Logger`：双缓冲异步落地，实例名打标；engine 内禁 printf。
- `NsClock`：steady(ns单调)+system(unix_ns) 双源封装。
- 错误码体系：`enum class Err : int16` 分段（1xx infra / 2xx storage / 3xx engine / 4xx net / 5xx authz），配 `ErrorMessage(Err)`；**全库返回 expected 风格 `Result<T>`**（C++17 手写轻量版，不用异常跨越 ABI）。

## 3. storage/ —— 存储层（L2）

### 3.1 TableStore
```
shm_TableDescriptor {
  magic, table_id(int64), name[64], create_ver;
  col_count; ColDef cols[MAX_INIT_COLS];         // 初始列布局
  ext_col_off; ext_col_count;                     // 在线加列扩展区描述
  rec_fixed_len; var_pool_head;
  row_cap; row_count; committed_row_count;
  ver_array_off; tombmap_off; data_seg_head_off;
  index_head_off[16]; table_rwlock;               // 每表最多16索引
}
struct ColDef { type:DataType; name[32]; offset; len; nullable; default_bits_off; }
```
- 行寻址 O(1)：`rec_ptr = data_base + row_no * rec_fixed_len`；
- 变长列记录内仅存 `(off,len)`；
- 删除=墓碑位置位+索引清键，行槽保留供覆盖复用（可配置 compact）。

### 3.2 WalGroupCommit
- 逻辑日志 `WalRec{ seq,u64 ts_ns, op(U/I/D/S), table_id, row_no, payload_len, payload }` 写环形缓冲；
- **组提交**：等待中的写请求打包一次 flush；fsync 策略三档（never/per_second/always）启动配置；
- 快照 = SuperBlock 记 checkpoint_seq 后 mmap 文件整体 rename，重启时"快照+回放(checkpoint_seq,尾]"。

**持久化语义（D1 拍板定案，2026-08，详见 docs/08 §2-D1）**：
WAL 环驻留**映像内**（不引入 sidecar WAL 文件）。进程崩溃（kill -9）下 mmap 共享页
与文件背衬一致，任何档位均零丢失；断电/内核崩溃下按档位区分：

| 档位 | 提交返回时 | 断电承诺 |
|---|---|---|
| always | 本组提交已 flush 全映像（头部+WAL+数据） | 已确认提交零丢失 |
| per_second（默认） | 写入页缓存即返回，后台节流 flush | 丢最近 ≤1s 窗口；进程崩溃不受影响 |
| never | 不主动 flush | 仅进程内一致 |

配套协议：环写满或即将覆盖 `checkpoint_seq` 后未 flush 记录时强制组刷并推进
checkpoint（"覆盖前先落盘"）；WAL 环写失败/校验失败 → 引擎毒化（kPoisoned）拒写保读。
per_second 的窗口语义为热路径 P99 ≤ 10μs（docs/05 §4）的达成前提，重放区间
`(checkpoint_seq, committed_seq]` 在上述协议下任意时刻完整可用。

### 3.3 Snapshot / Recovery
- 启动流程：open SuperBlock → 校验 crc → 定位 checkpoint → 重放 WAL 至尾部 → 发布 `committed_seq` → 状态 READY。

## 4. engine/ —— 引擎层（L3）

### 4.1 Catalog
- 两棵 SharedBTree（name/table_id）+ 描述符指针数组；建/删/改表的目录事务由 meta_rwmutex 保护，先写目录再迁移数据，崩溃后由 WAL 目录日志还原。
- 上限：默认 65535 表、每表 16 索引、128 列——全部 SuperBlock 配置化，**不再硬编码 1800/8/6**。

### 4.2 Engine（核心门面）
```
class Engine {
  Result<TableHandle> CreateTable(const TableDef&);
  Result<TableHandle> OpenTable(string_view name);
  Result<RowView>     Insert(TableHandle, span<const ColumnValue>);
  Result<RowView>     UpdateByKey(...); Result<void> DeleteByKey(...);
  BatchResult         ExecuteBatch(span<BatchOp>);      // 组提交批量
  Result<uint64>      UpsertBatch(RecordBlockView);     // 列式块upsert,百万点/s入口
  ScanCursor          Scan(table, filter_opt, order_opt);
  ChangeCursor        Subscribe(table_filter);
};
TableHandle = RAII 只读快照句柄：Open 时绑定 schema layout 版本，读全程免锁乐观读，
写入方在线加列不影响旧句柄读取。
```

### 4.3 IndexManager / ChangeLogStore / Authz / PerfCounters
- IndexManager：unique 冲突即失败；更新行=删旧键+插新键同事务记 WAL；可选延迟重建（BulkLoad 场景跳过维护事后 rebuild）。
- ChangeLogStore：环形持久区，读者持游标 `(seq)`；溢出策略可配（rewrite_snapshot/reject_slow_reader）。
- Authz：内置 user 表 + 盐哈希口令（PBKDF2 自实现）；权限=(db|table|col)×(r|w) 位图；token 本地签名校验。
- PerfCounters：shm 固定块的原子计数器组（qps/锁等待/索引命中率/wal backlog），CLI 直接展示。

## 5. server/ 与 client/

### 5.1 rtdbd 守护进程
单一进程承载（替代老 rtdbsrv/rsrvd/rtdbsync 三件套）：
- RPC 服务线程组（IOCP/epoll Reactor）：功能号 {AUTH, OPEN, EXEC_BATCH, SCAN_RANGE, SUBSCRIBE, FETCH_DELTA, DDL, PING}；
- 订阅推送会话管理：游标推进+背压（落后超阈值主动断开让客户端整表重取）；
- 可选加载 RDB 同步插件（dlopen/delay-load 按 IRdbSyncAdapter vtable）；
- 信号处理优雅退出做最终快照；watchdog 内嵌线程而非外部程序。

### 5.2 client 库
- `RtdbClient(host,port)`：连接池、自动重连、故障切换 writer 列表轮询；
- 本机同实例时自动降级为嵌入直连（探测共享内存存在性）——对上层完全透明；
- 订阅 API 回调式 `client.Subscribe(filter, [](DeltaBatch&){})`。
