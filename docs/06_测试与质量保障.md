# 06 测试与质量保障

## 1. 测试分层策略

| 层次 | 对象 | 手段 |
|---|---|---|
| 单元测试 | infra/btree/codec/authz/sql-parser 等纯逻辑 | GoogleTest；内存分配器可用 host heap 替身加速 |
| 组件测试 | TableStore/WAL/Engine（真实 shm 文件落 tmpdir） | 参数化：每条存储路径用例在 {win 文件映射, posix mmap} × {32,64 位} 组合跑 |
| 集成测试 | 嵌入多进程场景 + rtdbd ↔ client 双机 | pytest 驱动二进制起停 + gtest 自检进程 |
| 压力/混沌 | bench + 随机 kill 注入器 | 长稳 72h 无泄漏无死锁；kill 矩阵见 §3 |
| Fuzzing | 网络帧解析、SQL 解析器 | libFuzzer 目标（Linux CI 夜间）；协议 magic/crc 先校验再解析 |

## 2. 重点必测用例清单（摘选）
1. **IPC 锁死亡恢复**：持锁进程被 SIGKILL 后等待者超时夺锁并完成一致性标记；
2. **WAL 边界**：组提交中途中断 → 只承认 committed_seq 前；重放幂等；
3. **订阅游标**：慢读者压满 ChangeLog 环 → 按 overflow 策略得到明确错误而非静默丢数据；
4. **在线加列**：句柄跨 schema 版本读取；默认值位图生效；
5. **变长池碎片**：反复 insert/delete string/blob 后池空间回收率阈值测试；
6. **B+树顺序破坏**：乱序插入 10^7 键后有序遍历完整性 + 空间占用断言；
7. **字节序互通**：大端构造的帧在小端机解码正确（编解码层单独验证）。

## 3. 混沌注入矩阵（集成阶段每晚执行）
```
for each 注入点 in {Insert前,WAL追加中,commit标记前,索引更新一半,snapshot rename中}:
    启动写者 → 到达注入点 → kill -9 → 起动恢复流程 → 校验:
      (a) committed_seq 一致  (b) 无半截记录  (c) 订阅游标可续读
```

## 4. 覆盖率与门禁
- 行覆盖门槛：**全局 ≥ 80%**，由 CI 的 coverage job 以 `gcovr --fail-under-line 80` 强制（仅统计 `src/` 内核代码）；
- engine/ 与 storage/ 子目标 ≥ 85% 列为 M1 收敛目标（M0 验收实测：全局 86%，functions 95.6%）；
- PR 门禁：相关模块测试绿、sanitize job 绿；bench 基线劣化 >5% 阻断（M2 引入 bench 基线后生效）；
- clang-format/tidy 约定保留 `.clang-format/.clang-tidy` 供本地使用，暂不进 CI 强制（决策记录 2026-08-28）。

## 5. 用例规模与缺陷回归约定（2026-08 增补）

- 当前单测规模：**65 用例**（M0 验收 25 例；M1-W1~W3 新增 40 例，覆盖 schema 布局、
  变长池碎片回收、目录事务、行 CRUD 与变长池联动回收、列类型往返与损坏检出）；
  本地实测行覆盖 90%（GCC `--coverage` + gcovr，参数与 CI coverage job 一致）；
- **缺陷回归约定**：每个被修复的缺陷必须在对应单测套件补一条可复现该缺陷的用例后再提交
  修复——先例：`MVarLenPool` 小块（<40B）空闲链节点与尾标记重叠导致的重叠空闲块
  （用例 `VarPoolTest.TinyAllocationsRespectMinimumBlockAndStayIsolated`，详见 docs/03 §7.3）；
- **断言类问题必须用 Debug 配置验证**：`Result<T>` 的 `Error()`/`Value()` 带
  `assert(!IsOk())` / `assert(IsOk())` 守卫，Release（`NDEBUG`）会将其编译掉，
  因此"本地 Release 全绿"不能替代断言检查；提交前应以 Debug 配置各跑一遍
  （CI 的 `sanitize` 与 `coverage` 两个 job 均为 Debug 构建，正是该差异的暴露面）。
  先例：对成功的 `Result` 调用 `Error()`，本地 MSVC Release 全绿、CI Debug 直接中止；
- 组件测试使用真实临时映像文件（平台差异由 CI 双平台矩阵覆盖）；
  分配器/池类可用宿主堆缓冲替身加速（沿用本文 §1 分层策略）。
