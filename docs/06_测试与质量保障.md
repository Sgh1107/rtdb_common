# 06 测试与质量保障

## 1. 测试分层策略

| 层次 | 对象 | 手段 |
|---|---|---|
| 单元测试 | infra/btree/codec/authz/sql-parser 等纯逻辑 | GoogleTest；内存分配器可用 host heap 替身加速 |
| 组件测试 | TableStore/WAL/Engine（真实 shm 文件落 tmpdir） | 参数化：每条存储路径用例在 {win 文件映射, posix mmap} × {32,64 位} 组合跑 |
| 集成测试 | 嵌入多进程场景 + rtdbd ↔ client 双机 | pytest 驱动二进制起停 + gtest 自检进程 |
| 压力/混沌 | bench + 随机 kill 注入器 | 长稳 72h 无泄漏无死锁；kill 矩阵见 §3 |
| Fuzzing | 网络帧解析、SQL 解析器 | libFuzzer 目标（Linux CI 夜间）；协议 magic/crc 先校验再解析 |

## 2. 重点必测用例清单（摘选）
1. **IPC 锁死亡恢复**：持锁进程被 SIGKILL 后等待者超时夺锁并完成一致性标记；
2. **WAL 边界**：组提交中途中断 → 只承认 committed_seq 前；重放幂等；
3. **订阅游标**：慢读者压满 ChangeLog 环 → 按 overflow 策略得到明确错误而非静默丢数据；
4. **在线加列**：句柄跨 schema 版本读取；默认值位图生效；
5. **变长池碎片**：反复 insert/delete string/blob 后池空间回收率阈值测试；
6. **B+树顺序破坏**：乱序插入 10^7 键后有序遍历完整性 + 空间占用断言；
7. **字节序互通**：大端构造的帧在小端机解码正确（编解码层单独验证）。

## 3. 混沌注入矩阵（集成阶段每晚执行）
```
for each 注入点 in {Insert前,WAL追加中,commit标记前,索引更新一半,snapshot rename中}:
    启动写者 → 到达注入点 → kill -9 → 起动恢复流程 → 校验:
      (a) committed_seq 一致  (b) 无半截记录  (c) 订阅游标可续读
```

## 4. 覆盖率与门禁
- 行覆盖门槛：全局 ≥ 75%，engine/ 与 storage/ ≥ 85%；
- PR 门禁：clang-format diff 为空、tidy 无新增告警、相关模块测试绿、bench 基线不被劣化 >5%（夜间回归对比曲线入库）。
