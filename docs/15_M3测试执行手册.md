## 3. 环境与构建

### 3.1 双机环境建议

| 项 | 建议 |
|---|---|
| A 机（服务端） | Windows 10/11 或 Linux x86_64；4 核+、8 GB+；SSD |
| B 机（客户端） | 同 A；独立机器（不要与 A 同机回环混测） |
| 网络 | 同一受信内网；优先千兆/万兆直连或同交换机；避免 Wi-Fi |
| 地址 | A 固定 IP，例如 `192.168.10.10`；B 例如 `192.168.10.11` |
| 时间 | 两侧开启时间同步（Windows `w32tm /resync`；Linux `chronyc makestep`） |
| 防火墙 | A 放行 TCP 5599（最好只放行 B 的 IP） |
| 安全 | 协议为**明文 TCP + 摘要口令**，仅限受信内网；不要暴露公网 |

拓扑：

```text
┌──────────────────────────┐          TCP 5599          ┌──────────────────────────┐
│ A 机：rtdbd / remote_demo │ <========================> │ B 机：remote_demo /      │
│ 映像：m3lab.rtdb          │      受信内网 / 千兆       │ bench_net / 订阅客户端   │
└──────────────────────────┘                            └──────────────────────────┘
```

> 同一个映像文件只允许一个写者进程（rtdbd）。多机测试时，A 是唯一服务端；
> B 只做客户端，不要用 B 直接打开 A 的映像文件。

### 3.2 依赖

- CMake ≥ 3.16、C++17 编译器：
  - Windows：Visual Studio 2022（MSVC，CMakeLists 已加 `/utf-8`）
  - Linux：GCC 9+ 或 Clang 10+
- GoogleTest：
  - 默认配置期从 GitHub 拉取 v1.14.0；
  - 离线环境用 `-DRTDB_GTEST_ROOT=<gtest-root>`，目录约定
    `<root>/include/gtest/gtest.h`、`<root>/lib/gtest.lib`（Linux 为 `libgtest.a`）。
- 双机测试不需要在 B 机安装服务端依赖；但需要能运行 `remote_demo`/`bench_net`
  及对应 DLL/so。

### 3.3 Windows 构建

**方式 A：Visual Studio 多配置生成器（通用）**

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

**方式 B：Ninja 单配置（本仓库当前工作区就是这种）**

先打开 “x64 Native Tools Command Prompt for VS 2022”，或每次 call vcvars：

```powershell
cmd /c "call ""C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"" && cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build build -j 8"
```

> 如果 `build/` 已由另一种生成器（例如 VS）配置过，直接加 `-G Ninja` 会报
> 生成器不匹配。换一个目录（如 `build-ninja`）或删除 `build/` 后重新配置。

> 中文 Windows 下 `cl` 的 `showIncludes` 是本地化文本，CMake 可能读不到头文件
> 依赖。**改过头文件后先全量重编**：
> `cmake --build build --clean-first`，并设置 `VSLANG=1033`。
> 典型症状：`Options` 等结构体布局变化后，旧测试对象未重编，`Engine::Open`
> 误报 `invalid argument`。

### 3.4 Linux 构建

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

离线 GTest：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DRTDB_GTEST_ROOT=/opt/gtest
```

### 3.5 产物位置

| 生成器/平台 | rtdbd / bench_net / 单测 | remote_demo 等示例 |
|---|---|---|
| VS 多配置（Windows） | `build\Release\` | `build\bin\Release\` |
| Ninja 单配置（Windows） | `build\` | `build\bin\` |
| Linux 单配置 | `build/` | `build/bin/` |

本手册后面的命令用 `$B` 表示“二进制目录”：

```powershell
# Windows VS 多配置
$B = "build\Release"
$DEMO = "build\bin\Release"
# Windows Ninja
# $B = "build"; $DEMO = "build\bin"
```

```bash
# Linux
B=build
DEMO=build/bin
```

确认产物：

```powershell
Get-ChildItem $B\rtdbd.exe, $B\bench_net.exe, $B\rtdb_unit_tests.exe
Get-ChildItem $DEMO\remote_demo.exe
```

## 4. 本机测试（T0~T5）

### 4.1 T0：构建检查

- Release 构建零告警（`/W4` 或 `-Wall -Wextra`）。
- 构建后先确认测试能被发现：

```powershell
ctest --test-dir build -N
# 期望：Total Tests: 248
```

如果显示 `Total Tests: 0`，说明 `ctest` 跑错目录或没有配置测试；从 `build/`
目录执行，或使用 `--test-dir build`。

### 4.2 T1：全量单测（248 项）

```powershell
ctest --test-dir build -C Release --output-on-failure -j 1
```

判据：

- `100% tests passed, 0 tests failed out of 248`
- 任一项失败，先保留完整输出（不要只看最后一行）

证据：

```powershell
ctest --test-dir build -C Release --output-on-failure -j 1 `
  | Tee-Object -FilePath .\evidence_ctest.txt
```

> 建议 `-j 1`。部分用例使用固定临时映像名/端口，串行更可复现；CI 的并行
> 策略由 CMake 的 `RUN_SERIAL` 属性约束，但本地排查仍建议串行。

### 4.3 T2：定向功能回归

按模块跑，适合改完一处后快速验证：

| 模块 | ctest 过滤 | 直接 gtest 过滤 |
|---|---|---|
| WAL 环 / 保留 / 扩容 | `ctest -R "WalRingTest|WalEngineTest"` | `--gtest_filter="WalRingTest.*:WalEngineTest.*"` |
| 订阅 / 溢出 / 快照保留 | `ctest -R "SubscribeTest"` | `--gtest_filter="SubscribeTest.*"` |
| 快照 / 恢复 | `ctest -R "W5Snapshot"` | `--gtest_filter="W5SnapshotTest.*"` |
| 服务端协议 | `ctest -R "ServerTest|ServerConfig"` | `--gtest_filter="ServerTest.*:ServerConfig.*"` |
| 客户端 / 断连续传 | `ctest -R "ClientTest"` | `--gtest_filter="ClientTest.*"` |
| 行槽复用 / Upsert | `ctest -R "EngineCrudTest|EngineConcurrencyTest"` | `--gtest_filter="EngineCrudTest.*:EngineConcurrencyTest.*"` |
| C ABI / Native API | `ctest -R "CAbiTest|NativeApiTest"` | `--gtest_filter="CAbiTest.*:NativeApiTest.*"` |
| 混沌（单轮） | `ctest -R "NetChaos"` | `--gtest_filter="NetChaos.*"` |

> 上表的 ctest 只写了过滤片段；完整写法是
> `ctest --test-dir build -C Release -R "..."`（Linux 去掉 `-C Release`）。

例子：

```powershell
# 只跑 P0-5 相关
& "$B\rtdb_unit_tests.exe" `
  --gtest_filter="WalRingTest.*:WalEngineTest.*:SubscribeTest.SnapshotDoesNotEvictActiveCursor:SubscribeTest.RingPressureKeepsRecentWindowForLaggingCursor:W5SnapshotTest.SnapshotAdvancesCheckpointKeepsRingHistory:ServerConfig.ParseTextListenAndValidation"
```

### 4.4 T3：本机端到端演示

两个终端（`$DEMO` 见 §3.5）：

**终端 1（服务端，自带周期写）**

```powershell
& "$DEMO\remote_demo.exe" --serve --listen 127.0.0.1:5599 --rows 3 --write-ms 300
```

**终端 2（客户端）**

```powershell
& "$DEMO\remote_demo.exe" --host 127.0.0.1 --port 5599 --seconds 10
```

期望：

- 服务端打印 `rtdbd 核心已监听 127.0.0.1:5599`、`演示表 demo 就绪`；
- 客户端打印 `已连接`、`PING`、`订阅就绪`；
- 逐条 `#N seq=... insert`，`seq` 严格递增；
- 结束打印 `已收变更 N 条`，N > 0；
- 服务端退出时 `服务端统计` 中 `帧违例/载荷错误` 为 0（收尾 EOF 可能计入
  `frame_errors`，属正常；`payload_errors` 必须为 0）。

### 4.5 T4：混沌（kill/重启/续传）

Linux / Git Bash：

```bash
scripts/chaos_m3.sh 20
```

它会：

- 定位 `build/rtdb_unit_tests(.exe)`（也可用 `RTDB_TEST_BIN` 指定）；
- 跑 `NetChaos.Kill9RestartResumesDelivery` 与
  `NetChaos.KillDuringWriteBurstSustainsDelivery` 各 20 轮；
- 日志写入 `build/chaos_m3_<时间戳>.log`。

判据：

- `chaos_m3: 全部 20 轮通过`；
- 日志中失败计数为 0；
- 重点是“已应答（acked）的写入最终必达”和“交付 seq 严格递增、无缺漏”。

Windows 没有 bash 时，可直接：

```powershell
& "$B\rtdb_unit_tests.exe" --gtest_filter="NetChaos.*" --gtest_repeat=20 --gtest_break_on_failure
```

### 4.6 T5：回环性能

```powershell
# 正式规模（进程内 rtdbd；约 200k 行）
& "$B\bench_net.exe"

# CI 门禁口径（50k 行，带阈值断言）
& "$B\bench_net.exe" --ci
```

关注输出：

```text
BENCHNET block rows_per_sec=... req_per_sec=... rows=... secs=...
BENCHNET ops   rows_per_sec=... req_per_sec=... rows=... secs=...
BENCHNET ping_us  p50=... p99=... max=... (n=...)
BENCHNET write1_us p50=... p99=... max=... (n=...)
BENCHNET sub_us   p50=... p99=... max=... (n=...)
BENCHNET RESULT PASS
```

判据：

- `BENCHNET RESULT PASS`；
- `block rows_per_sec` ≥ 200,000（本机历史基线 211,558）；
- `sub_us p99` ≤ 1,000µs（本机出口 #4；历史基线 133.7µs）；
- `ping_us/write1_us p99` 在毫秒级以内。

> 回环数字只作为基线，**不能**替代双机出口值；不要把两者混记。

## 5. 服务端部署（双机测试的 A 机）

有两种服务端形态：

1. **`remote_demo --serve`**：进程内起 `server::Server`，自带 `demo` 表、
   `demo/demo123/demo-salt` 默认认证和周期写。适合演示、续传、快速联调。
2. **`rtdbd --config`**：正式服务进程，配置、用户、WAL 环、退出行为都可控。
   适合正式双机验收与基准。

### 5.1 生成口令摘要

约定：摘要 = `SHA-256(salt || password)`，盐为部署共享值（不是机密，但也不要
和公网口令复用）。

```powershell
& "$B\rtdbd.exe" --hash-password demo123 --salt m3-lab-salt
# 输出 64 位十六进制，例如：
# 1315cb9f...（每次盐/口令相同则结果相同）
```

Linux：

```bash
./build/rtdbd --hash-password demo123 --salt m3-lab-salt
```

### 5.2 配置文件模板（A 机）

保存为 `m3lab.cfg`（ASCII/UTF-8，`#` 注释，未知键会被拒绝）：

```ini
# ---- 实例与映像 ----
instance = m3lab
path = D:/rtdb/m3lab.rtdb
size_mb = 256
wal_ring_kb = 0

# ---- 网络 ----
listen = 0.0.0.0:5599

# ---- 持久化 ----
fsync = per_second

# ---- 认证 ----
auth_salt = m3-lab-salt
user = demo <把 --hash-password 的 64 位输出粘到这里>
# 可选：给 bench_net 专用账号
# user = bench <bench-pw + bench-salt 的摘要>

# ---- 会话/超时 ----
session_ttl_ms = 1800000
max_sessions = 64
handshake_timeout_ms = 10000
idle_timeout_ms = 300000
max_auth_failures = 5
auth_backoff_ms = 200

# ---- 帧/订阅预算 ----
max_payload_kb = 4096
heartbeat_ms = 1000
max_delta_kb = 1024
delta_max_timeout_ms = 25000

# ---- 退出 ----
snapshot_on_exit = false
```

要点：

- `size_mb`：1~4096；新建映像时生效。默认 256。
- `wal_ring_kb`：`0` = 引擎默认 64KB；否则 64~65536。**只在新建映像时生效**；
  已有映像以 `SuperBlock.wal_ring_bytes` 为准。改这个值不会改变旧映像的环。
- `listen = 0.0.0.0:5599` 才会对外；默认只绑 `127.0.0.1`。
- 正式出口基线建议用默认 `0`（64KB），与 `docs/14` 的回环基线同口径；P0-5 大环
  验证再改成 `1024`（见 §6.5）。无论选哪个，三次复跑必须一致并在证据中记录。
- `snapshot_on_exit=true` 会在优雅退出时抓 `.snap`，不影响本次测试；需要干净
  重启时建议 false。

### 5.3 启动与停止

```powershell
# A 机（$B 见 §3.5；配置文件路径按需改）
& "$B\rtdbd.exe" --config .\m3lab.cfg

# 只对本次进程覆盖监听/路径（CLI 优先级高于配置文件）
& "$B\rtdbd.exe" --config .\m3lab.cfg --listen 0.0.0.0:5599 --path D:/rtdb/m3lab.rtdb

# 自动化烟测：N 毫秒后优雅退出，退出码 0
& "$B\rtdbd.exe" --config .\m3lab.cfg --exit-after-ms 60000
```

停止：

- 优雅：`Ctrl+C`（Windows 控制台事件 / Linux SIGINT）。
- 硬杀（续传测试用）：Windows `taskkill /IM rtdbd.exe /F`（先确认没有别的
  rtdbd 实例）；Linux `pkill -9 -x rtdbd`。
- 查看端口占用：`Get-NetTCPConnection -LocalPort 5599` 或
  `netstat -ano | findstr :5599`。

### 5.4 防火墙

Windows（管理员 PowerShell）：

```powershell
# 只放行 B 机
netsh advfirewall firewall add rule name="rtdb 5599 from B" dir=in action=allow protocol=TCP localport=5599 remoteip=<B-IP>
# 测试结束删除
netsh advfirewall firewall delete rule name="rtdb 5599 from B"
```

Linux：

```bash
sudo ufw allow from <B-IP> to any port 5599 proto tcp
sudo ufw delete allow from <B-IP> to any port 5599 proto tcp
```

### 5.5 连通性预检（B 机）


```bash
ping -c 4 <A-IP>
```

防火墙、IP/网段，不要先怀疑协议。

## 6. 双机测试（T6/T7，核心）

### 6.1 D1：双机订阅演示（remote_demo）

**A 机**（自带服务端 + 周期写；不要同时跑 rtdbd 占 5599）：

```powershell
& "$DEMO\remote_demo.exe" --serve --listen 0.0.0.0:5599 --rows 3 --write-ms 300
```

**B 机**：

```powershell
& "$DEMO\remote_demo.exe" --host <A-IP> --port 5599 --seconds 30
```

期望输出（B 机）：

```text
已连接 <A-IP>:5599（会话 ...）
PING：committed_seq=... 心跳=... ttl=...
表 demo：3 列（id, val, msg）
订阅就绪
#1 seq=... insert 表=demo 行=[...]
...
已收变更 N 条；关闭订阅与连接…
```

判定：

- `订阅就绪` 出现；
- `seq` 严格递增（允许重复，不允许前向跳号）；
- `N > 0`；
- A 机 Ctrl+C 优雅退出时统计中 `payload_errors=0`。

保存证据：

```powershell
& "$DEMO\remote_demo.exe" --host <A-IP> --port 5599 --seconds 30 `
  | Tee-Object -FilePath .\evidence_demo_B.txt
```

### 6.2 D2：双机吞吐与延迟（bench_net）

#### 6.2.1 方式一：快速联调（复用 remote_demo 服务端）

A 机：

```powershell
& "$DEMO\remote_demo.exe" --serve --listen 0.0.0.0:5599 --rows 0 --write-ms 0 --exit-after-ms 600000
```

B 机（使用 remote_demo 的默认账号）：

```powershell
& "$B\bench_net.exe" --host <A-IP> --port 5599 `
  --user demo --password demo123 --salt demo-salt `
  --rows 200000 --batch 512 `
  --table ("bench_quick_" + (Get-Date -Format "yyyyMMdd_HHmmss"))
```

> `--table` 每次用新名字：`bench_net` 外部模式不会删除/重建已有表，重复使用
> 同一个表名时，ops 阶段会因主键已存在而失败（`already exists`）。

#### 6.2.2 方式二：正式验收（rtdbd + 专用 bench 账号）

A 机：先给 bench 账号生成摘要，写入 `m3lab.cfg`：

```powershell
& "$B\rtdbd.exe" --hash-password bench-pw --salt bench-salt
# 配置中增加：
# user = bench <上一条输出的 64hex>
```

启动：

```powershell
& "$B\rtdbd.exe" --config .\m3lab.cfg
```

B 机：

```powershell
& "$B\bench_net.exe" --host <A-IP> --port 5599 `
  --user bench --password bench-pw --salt bench-salt `
  --rows 200000 --batch 512 `
  --table ("bench_exit_" + (Get-Date -Format "yyyyMMdd_HHmmss"))
```

`bench_net` 默认是进程内模式；指定 `--host` 或 `--port` 即切到外部模式。
外部模式下它会在 A 机建表 `bench_exit_*`（M3 无 RBAC，认证用户可 DDL）。

#### 6.2.3 输出与判据

关键行：

```text
BENCHNET block rows_per_sec=...
BENCHNET sub_us p50=... p99=... max=... (n=...)
BENCHNET RESULT PASS
```

| 出口项 | 取值 | 判据 |
|---|---|---|
| 批量吞吐（跨机千兆） | `BENCHNET block rows_per_sec` | ≥ 200,000 行/s |
| 订阅端到端延迟（跨机） | `BENCHNET sub_us p99` | < 50,000 µs（50ms） |
| 单条写/PING | `write1_us/ping_us p99` | 记录即可；异常时排查 |
| 结果 | `BENCHNET RESULT PASS` | 必须 PASS |

要求：

- 至少跑 **3 轮**，每轮使用新的 `--table`；
- 记录每轮原始输出，取中位数作为结论；
- 三轮之间不要改 `wal_ring_kb`、`fsync`、`rows/batch`；
- 不要把回环基线（`docs/14 §6.2`，P99 133.7µs、211k 行/s）当成跨机结果。

证据示例：

```powershell
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
& "$B\bench_net.exe" --host <A-IP> --port 5599 `
  --user bench --password bench-pw --salt bench-salt `
  --rows 200000 --batch 512 --table "bench_exit_$ts" `
  | Tee-Object -FilePath ".\evidence_bench_$ts.txt"
```

### 6.3 D3：双机断连续传（kill/重启 A 机）

**目标**：B 机订阅不断线重连后，从上次位置继续；允许重复，不允许缺漏。

#### 步骤

1. A 机启动带周期写的服务端（`remote_demo` 最简单）：

```powershell
& "$DEMO\remote_demo.exe" --serve --listen 0.0.0.0:5599 --rows 3 --write-ms 200
```

2. B 机启动订阅并把输出落盘：

```powershell
& "$DEMO\remote_demo.exe" --host <A-IP> --port 5599 --seconds 180 `
  | Tee-Object -FilePath .\evidence_reconnect_B.txt
```

3. 观察到若干条 `#N seq=...` 后，在 A 机**硬杀**（只在 A 机执行，避免误杀
   B 机客户端）：

```powershell
taskkill /IM remote_demo.exe /F
```

4. 等 3~5 秒，在**同一个工作目录**再启动 A 机（默认映像 `remote_demo.img`
   在当前目录；换目录会得到空库）。为了让重启后还能继续产生新写入，把
   `--rows` 调到明显大于断前最大主键（例如断前约 150 条时用 1000；如果断前
   已超过 1000，就用更大的值）：

```powershell
& "$DEMO\remote_demo.exe" --serve --listen 0.0.0.0:5599 --rows 1000 --write-ms 200
```

> 重启时预置的 1..1000 行中，已存在的会被忽略、新行会补写；B 会收到一段
> 补发事件，这是预期行为。若 `--rows` 小于断前最大主键，周期写会卡在重复
> 主键上不再前进，测试就失去意义。

5. B 机应打印：

```text
订阅重连中（第 1 次）…
订阅就绪
#N seq=... insert ...
```

6. 结束后检查 B 机日志的 seq 序列：

```powershell
$seqs = Select-String -Path .\evidence_reconnect_B.txt -Pattern '#\d+ seq=(\d+)' |
  ForEach-Object { [int64]$_.Matches[0].Groups[1].Value }
$gaps = 0
for ($i = 1; $i -lt $seqs.Count; ++$i) {
  if ($seqs[$i] -gt $seqs[$i - 1] + 1) { $gaps++ }
}
"count=$($seqs.Count) gaps=$gaps first=$($seqs[0]) last=$($seqs[-1])"
```

判定：

- `gaps=0`（允许重复：`seq` 等于前一条或更小）；
- 重连后首条 seq ≤ 断前最后 seq + 1；
- 如果出现 `订阅游标越窗…整表重取`，说明断线时间超过了环保留窗口；
  这是**允许的恢复路径**，但要确认“重扫完成：N 行”，并单独记录，不能把
  重扫后的跳号误判为缺漏。

> 本机混沌用例（§4.5）已经在进程级严格验证 acked ⊆ 交付、seq 无前向跳号；
> 双机手工测试重点验证真实网络断连/重连与客户端退避。

### 6.4 D4：环压力与溢出重同步（可选，P0-5 相关）

## 9. 常见问题排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| B 机 `Connection refused` | A 未监听/只听回环/端口错 | A 用 `0.0.0.0:5599`；`Get-NetTCPConnection` 查端口；B `Test-NetConnection` |
| B 机连接超时 | 防火墙/网段/路由 | 放行 TCP 5599；`ping`/`tracert`；确认 A IP |
| `AUTH failed` / 501 | 盐或口令摘要不一致 | 用 A 的 `auth_salt` 重新 `--hash-password`；配置 `user = 名 <64hex>` |
| `session ... 502` | 会话过期/服务端重启 | 客户端重连/重新认证；检查 `session_ttl_ms` |
| `402` / `kCursorOverflow` | 订阅游标落后于 WAL 保留窗口 | 正常恢复路径：整表重取 + `ResetTo`；需要更长窗口就加大 `wal_ring_kb`（新映像） |
| `306` / `configured limit exceeded` | 单批超过 WAL 记录区容量 | 降低 `--batch`，或新建映像并加大 `wal_ring_kb` |
| `kOutOfMemory`（启动/建表） | 映像太小，放不下环/表 | 增大 `size_mb`；环容量需小于映像可用空间 |
| 改 `wal_ring_kb` 不生效 | 已有映像不改环 | 删除 `.rtdb`/`.snap` 重建，或换新 `path` |
| `bench ops batch failed: already exists` | 外部模式复用了旧表 | 每次用新的 `--table`，或重建 A 的映像 |
| `invalid argument`（Engine::Open） | 非法 `wal_ring_bytes`/`size_mb`；或旧测试对象布局不匹配 | 检查配置范围；改头文件后 `--clean-first` 全量重编 |
| `ctest: Total Tests: 0` | 在源码根执行/未配置测试 | `ctest --test-dir build` 或 `cd build` |
| 测试结果与上次不同 | 残留映像/端口/并行 | 删除 `build/rtdb_gtest_*`、确认端口；用 `-j 1` |
| 中文 Windows 构建不重编头文件依赖 | `showIncludes` 本地化 | 设置 `VSLANG=1033`，或 `--clean-first` |
