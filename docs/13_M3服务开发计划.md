## 3. 关键架构决策（D1~D8）

### D1 订阅数据源 = WalRing 复用（不新增 ChangeLogStore）

- 变更记录源即 WAL 环：`(checkpoint_seq, committed_seq]` 恒完整可用（docs/03 §3.2 覆盖协议
  已保证）；订阅窗口 = 环容量（当前 64KB）内未回收的提交段。
- 新增读面：`WalRing::ScanRange(from_excl, to_incl, max_bytes, fn)`——从 tail 顺序扫描、
  跳过 ≤from 的记录、按剩余字节预算交付，调用方持根锁（扫描 ≤64KB，微秒级）。
- **交付上界 = `committed_seq`**：任何 seq ≤ committed_seq 的记录，其所在批必已 COMMIT 且已
  应用（引擎仅在 COMMIT 落环并应用后推进 committed_seq），逐条交付不含半批风险；
  BEGIN/COMMIT 标记不对外交付。
- 溢出判据：`from_seq + 1 < ring.oldest_seq()` → `kCursorOverflow`（新增错误码 402）。

### D2 网络订阅 = SUBSCRIBE 注册 + FETCH_DELTA 长轮询（非服务端自发推送）

- `FETCH_DELTA(from_seq, max_bytes, timeout_ms)`：服务端在新数据出现（D4 唤醒）或超时后应答；
  游标由请求携带（服务端不持权威游标），ACK 仅用于背压账本与诊断。
- 理由：与阻塞 I/O 线程模型天然配合（D3）；背压/限流语义简单（应答即窗口）；断线恢复时
  客户端凭 last acked seq 直接续传，无服务端状态重建问题；时效目标（本机 ≤1ms、跨机
  P99 ≤50ms）由"长轮询 + 唤醒"达成，与推送等价。
- 协议功能号沿用 docs/04 §5（AUTH=1 PING=2 DDL=10 EXEC_BATCH=11 SCAN=12 SCAN_PAGE=13
  SUBSCRIBE=20 FETCH_DELTA=21 ACK=22 UNREGISTER=23），只增不改。

### D3 传输线程模型 = 阻塞 socket + 线程/会话（反应堆顺延）

- `rtdbd`：acceptor 线程 + 每连接一个会话线程（阻塞收发 + 超时）；会话数设上限，
  超限拒绝新连接（404 kTooManySessions）。
- 依据：出口吞吐（≥200k 行/s）与演示规模（数会话）在阻塞模型下有充分余量；双平台实现
  与调试成本最低。`INetTransport` 抽象保留，反应堆实现可在不改协议/业务层的前提下替换。
- 客户端：请求-应答同步 + 订阅泵线程；连接断开后指数退避重连。

### D4 跨进程变更唤醒 = platform `Wait32/WakeAll32`（futex / WaitOnAddress）

- 等待字 = `SuperBlock.committed_seq` **低 32 位**（免布局变更；64 位全量值在等待前后
  复核）。语义与 futex 一致：等待时校验期望值，值已变即立即返回；唤醒调用仅是加速，
  超时兜底——**无丢失唤醒风险**。
- 平台实现：Linux `syscall(SYS_futex, FUTEX_WAIT/FUTEX_WAKE)`（同一物理页跨进程有效）；
  Win32 `WaitOnAddress/WakeByAddressAll`（Windows 8+）。自旋（前若干 µs）→ 等待混合。
- 用途：嵌入 `ChangeCursor::Next`、rtdbd 的 FETCH_DELTA 长轮询共享此原语。

### D5 网络量编码 = 类型化行/键 + 列式块

- 标量统一 i64/f64 线形（i8/i16/i32/i64/bool/时间戳 → i64；float32/64 → f64），变长列
  `[u32 len][bytes]`，空值由逐值 tag（0=NULL/1=i64/2=f64/3=var）承载。
- EXEC_BATCH 双模式：`mode=0` 操作表（对齐 `ExecuteBatch`）；`mode=1` 列式块（对齐
  `UpsertBatch`/`RecordBlock`，列数组 + 类型标注）。
- 订阅增量：逐条 `{seq, ts_ns, table(名), op, row_no, row_ver, 行值或主键}`；update/insert
  携带 WAL 载荷解码后的整行值（服务端经 `TableStore::DecodeRecord` 复用路径解码）。
- 帧：`[magic'RTDB'][ver u8][flags u8][session u32][func u16][payload_len u32][crc u32][payload]`
  （20B 定长头；CRC 覆盖头+载荷；响应 = 同 func + flags 应答位）。所有多字节小端。
- 载荷上限（默认 4MB，可配）与 CRC 校验失败 → 断开连接（kProtocolError 4xx 新增为人读码）。

### D6 认证最小面 = 配置用户表 + 会话 token

- 服务端配置内联 `user = sha256(salt || password)`（盐在配置中，非机密）；AUTH 成功发放
  随机 128-bit **会话号**（帧头 session 字段），带 TTL 滚动续期；超时/非法会话 → 501/502。
- 角色：M3 仅"读写管理员"一类（写 + DDL）；只读账号与权限位图归 M4。
- 明示边界：抗明文口令抓包（不回传口令），不抗重放/窃听——局域网明文，TLS 归 M4。

### D7 服务面 = rtdbd 单进程、写者角色、优雅退出

- 命令行/配置：实例名、映像路径、监听地址:端口、fsync 档、用户表、快照开关。
- 优雅退出（SIGINT/SIGTERM/控制台事件）：停止 accept → 通知会话收尾（限时）→ 可选终场快照
  → 引擎析构（组提交终刷）。写者心跳线程周期更新 `writer_heartbeat_ns`；陈旧心跳可供
  客户端只读降级探测（完整主备仲裁归 M4）。

### D8 兼容性承诺

- C ABI：v2 只增符号（订阅族 `rtdb_abi_sub*`），v1 符号语义与签名不动（`RTDB_ABI_VERSION` 2）。
- 协议：功能号/字段只增不改；v1 解析器遇未知功能号回 `kUnsupported`（不断连）。
- 共享内存布局：**不递增 `kShmFormatVersion`**（D4 不引入新字段；M3 全部新增位于网络/进程层）。

## 6. 测试与质量保障

- **单元**：帧编解码（往返/截断/超长/CRC 错误/未知功能号）、值编解码（全类型 + NULL +
  越界长度）、ScanRange（预算截断/回绕/撕裂尾）、游标溢出判据、配置解析、过滤器匹配。
- **集成（进程内，127.0.0.1 临时端口）**：AUTH 成功/失败/过期；DDL 幂等；批量 ≥10 万行
  分片；分页扫描；订阅端到端（写→长轮询收到，序严格递增）；断连续传（丢包模拟=直接
  关连接）；溢出重取（压缩环窗口后追赶）；慢读者背压；多会话并发；优雅退出（不朽在途写）。
- **进程级（spawn）**：`rtdbd` 实例拉起 → 客户端连通 → kill -9 → 重启 → 客户端自动重连
  续传；写者心跳陈旧探测。
- **性能**：`tools/bench_net` 记录吞吐/延迟两档数值；ctest 内仅做保守下限断言（回环
  ≥50k 行/s 与 P99 ≤5ms 量级），避免 CI 环境抖动误报；正式基线以本机实测记录入 docs/14。
- **混沌**：脚本化"杀服务端/断客户端 ×N + 重连续传校验"；与 M1 混沌脚本风格一致。

| 风险 | 影响 | 对策 |
|---|---|---|
| 环容量仅 64KB，订阅窗口偏小（断线即溢出） | 续传演示需频整表重取 | 演示节奏控制 + 溢出重取语义完整实现；环扩容（可配/分片）列为数据量驱动项 |

## 8. 落地差异记录（执行期追加）

- （W1 起逐项记录与本文档的差异、决策调整与证据。）

### W2 落地记录（嵌入订阅 + C ABI v2）

- **变长列交付语义（重要修正）**：WAL 记录对内联定长列是自包含的，但
  `kUtf8Var/kBytesVar` 列仅存"表内池（off,len）引用"——覆盖写会回收旧块
  （`ReleaseRecordVars`），马后解码会读到已回收/复用字节。落地判据：
  **仅当事件仍为行当前版本（row_no/row_ver 相同且未墓碑）时解码交付真实
  值，否则该列交付 NULL**（`TableStore::DecodeWalRow` + `IsCurrentRowVersion`）。
  语义上："事件行的定长列 = 精确写入值；变长列在其行版本未被取代时精确、
  被取代后为 NULL（消费方按主键重取）"。扫描在根锁内进行，版本判定与池
  读取对写路径原子（网络/嵌入两路共用同一解码面）。
  备选（推迟池块回收至环丢弃 / 变长字节内嵌 WAL 载荷）因内存无界与恢复
  面改造代价被否；如后续需要"历史变长值订阅"，应走 WAL 载荷自包含化。
- **C ABI**：v2 只增符号（订阅族）；`RTDB_ABI_VER` 随能力递增为 2（既有
  v1 符号语义/签名未变），`scripts/cabi_smoke.py` 期望值同步。
- **等值提交唤醒**：`MarkCommitted` 侧统一 `WakeAll32`（futex/WaitOnAddress
  等待字 = committed_seq 低 32 位）；WaitOnAddress/futex 跨进程生效，故
  单写者与多写者嵌入场景均不依赖轮询（超时参数仍为服务端兜底）。
- **测试证据**：`TestScanRange*`（回绕/窗口/回调停止/预算截断/撕裂尾/溢出
  判据）+ `TestSubscribe*`（三事件内容、过滤、批原子边界、超时空批、溢出重
  同步、并发写无丢失/无重复、扩展列、变长列版本门、拒绝面）+ `CAbiTest.
  SubscribeCursorNextDeliversEvents`；全量 202/202 通过（W1 后新增 15 用例）。
