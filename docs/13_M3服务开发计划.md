## 3. 关键架构决策（D1~D8）

### D1 订阅数据源 = WalRing 复用（不新增 ChangeLogStore）

- 变更记录源即 WAL 环：`(checkpoint_seq, committed_seq]` 恒完整可用（docs/03 §3.2 覆盖协议
  已保证）；订阅窗口 = 环容量（当前 64KB）内未回收的提交段。
- 新增读面：`WalRing::ScanRange(from_excl, to_incl, max_bytes, fn)`——从 tail 顺序扫描、
  跳过 ≤from 的记录、按剩余字节预算交付，调用方持根锁（扫描 ≤64KB，微秒级）。
- **交付上界 = `committed_seq`**：任何 seq ≤ committed_seq 的记录，其所在批必已 COMMIT 且已
  应用（引擎仅在 COMMIT 落环并应用后推进 committed_seq），逐条交付不含半批风险；
  BEGIN/COMMIT 标记不对外交付。恢复期丢弃无 COMMIT 整批时同步回退写头
  （`head_seq/head_pos` 退到有效前缀末尾），维持 seq 连续与该不变量（§8-W5 本轮修复记录）。
- 溢出判据：`from_seq + 1 < ring.oldest_seq()` → `kCursorOverflow`（新增错误码 402）。

### D2 网络订阅 = SUBSCRIBE 注册 + FETCH_DELTA 长轮询（非服务端自发推送）

- `FETCH_DELTA(from_seq, max_bytes, timeout_ms)`：服务端在新数据出现（D4 唤醒）或超时后应答；
  游标由请求携带（服务端不持权威游标），ACK 仅用于背压账本与诊断。
- 理由：与阻塞 I/O 线程模型天然配合（D3）；背压/限流语义简单（应答即窗口）；断线恢复时
  客户端凭 last acked seq 直接续传，无服务端状态重建问题；时效目标（本机 ≤1ms、跨机
  P99 ≤50ms）由"长轮询 + 唤醒"达成，与推送等价。
- 协议功能号沿用 docs/04 §5（AUTH=1 PING=2 DDL=10 EXEC_BATCH=11 SCAN=12 SCAN_PAGE=13
  SUBSCRIBE=20 FETCH_DELTA=21 ACK=22 UNREGISTER=23），只增不改。

### D3 传输线程模型 = 阻塞 socket + 线程/会话（反应堆顺延）

- `rtdbd`：acceptor 线程 + 每连接一个会话线程（阻塞收发 + 超时）；会话数设上限，
  超限拒绝新连接（404 kTooManySessions）。
- 依据：出口吞吐（≥200k 行/s）与演示规模（数会话）在阻塞模型下有充分余量；双平台实现
  与调试成本最低。`INetTransport` 抽象保留，反应堆实现可在不改协议/业务层的前提下替换。
- 客户端：请求-应答同步 + 订阅泵线程；连接断开后指数退避重连。

### D4 跨进程变更唤醒 = platform `Wait32/WakeAll32`（futex / WaitOnAddress）

- 等待字 = `SuperBlock.committed_seq` **低 32 位**（免布局变更；64 位全量值在等待前后
  复核）。语义与 futex 一致：等待时校验期望值，值已变即立即返回；唤醒调用仅是加速，
  超时兜底——**无丢失唤醒风险**。
- 平台实现：Linux `syscall(SYS_futex, FUTEX_WAIT/FUTEX_WAKE)`（同一物理页跨进程有效）；
  Win32 `WaitOnAddress/WakeByAddressAll`（Windows 8+）。自旋（前若干 µs）→ 等待混合。
- 用途：嵌入 `ChangeCursor::Next`、rtdbd 的 FETCH_DELTA 长轮询共享此原语。

### D5 网络量编码 = 类型化行/键 + 列式块

- 标量统一 i64/f64 线形（i8/i16/i32/i64/bool/时间戳 → i64；float32/64 → f64），变长列
  `[u32 len][bytes]`，空值由逐值 tag（0=NULL/1=i64/2=f64/3=var）承载。
- EXEC_BATCH 双模式：`mode=0` 操作表（对齐 `ExecuteBatch`）；`mode=1` 列式块（对齐
  `UpsertBatch`/`RecordBlock`，列数组 + 类型标注）。
- 订阅增量：逐条 `{seq, ts_ns, table(名), op, row_no, row_ver, 行值或主键}`；update/insert
  携带 WAL 载荷解码后的整行值（服务端经 `TableStore::DecodeRecord` 复用路径解码）。
- 帧：`[magic'RTDB'][ver u8][flags u8][session u32][func u16][payload_len u32][crc u32][payload]`
  （20B 定长头；CRC 覆盖头+载荷；响应 = 同 func + flags 应答位）。所有多字节小端。
- 载荷上限（默认 4MB，可配）与 CRC 校验失败 → 断开连接（kProtocolError 4xx 新增为人读码）。

### D6 认证最小面 = 配置用户表 + 会话 token

- 服务端配置内联 `user = sha256(salt || password)`（盐在配置中，非机密）；AUTH 成功发放
  随机 128-bit **会话号**（帧头 session 字段），带 TTL 滚动续期；超时/非法会话 → 501/502。
- 角色：M3 仅"读写管理员"一类（写 + DDL）；只读账号与权限位图归 M4。
- 明示边界：抗明文口令抓包（不回传口令），不抗重放/窃听——局域网明文，TLS 归 M4。

### D7 服务面 = rtdbd 单进程、写者角色、优雅退出

- 命令行/配置：实例名、映像路径、监听地址:端口、fsync 档、用户表、快照开关。
- 优雅退出（SIGINT/SIGTERM/控制台事件）：停止 accept → 通知会话收尾（限时）→ 可选终场快照
  → 引擎析构（组提交终刷）。写者心跳线程周期更新 `writer_heartbeat_ns`；陈旧心跳可供
  客户端只读降级探测（完整主备仲裁归 M4）。

### D8 兼容性承诺

- C ABI：v2 只增符号（订阅族 `rtdb_abi_sub*`），v1 符号语义与签名不动（`RTDB_ABI_VERSION` 2）。
- 协议：功能号/字段只增不改；v1 解析器遇未知功能号回 `kUnsupported`（不断连）。
- 共享内存布局：**不递增 `kShmFormatVersion`**（D4 不引入新字段；M3 全部新增位于网络/进程层）。

## 6. 测试与质量保障

- **单元**：帧编解码（往返/截断/超长/CRC 错误/未知功能号）、值编解码（全类型 + NULL +
  越界长度）、ScanRange（预算截断/回绕/撕裂尾）、游标溢出判据、配置解析、过滤器匹配。
- **集成（进程内，127.0.0.1 临时端口）**：AUTH 成功/失败/过期；DDL 幂等；批量 ≥10 万行
  分片；分页扫描；订阅端到端（写→长轮询收到，序严格递增）；断连续传（丢包模拟=直接
  关连接）；溢出重取（压缩环窗口后追赶）；慢读者背压；多会话并发；优雅退出（不朽在途写）。
- **进程级（spawn）**：`rtdbd` 实例拉起 → 客户端连通 → kill -9 → 重启 → 客户端自动重连
  续传；写者心跳陈旧探测。
- **性能**：`tools/bench_net` 记录吞吐/延迟两档数值；ctest 内仅做保守下限断言（回环
  ≥50k 行/s 与 P99 ≤5ms 量级），避免 CI 环境抖动误报；正式基线以本机实测记录入 docs/14。
- **混沌**：脚本化"杀服务端/断客户端 ×N + 重连续传校验"；与 M1 混沌脚本风格一致。

## 8. 落地差异记录（执行期追加）

- （W1 起逐项记录与本文档的差异、决策调整与证据。）

### W2 落地记录（嵌入订阅 + C ABI v2）

- **变长列交付语义（重要修正）**：WAL 记录对内联定长列是自包含的，但
  `kUtf8Var/kBytesVar` 列仅存"表内池（off,len）引用"——覆盖写会回收旧块
  （`ReleaseRecordVars`），马后解码会读到已回收/复用字节。落地判据：
  **仅当事件仍为行当前版本（row_no/row_ver 相同且未墓碑）时解码交付真实
  值，否则该列交付 NULL**（`TableStore::DecodeWalRow` + `IsCurrentRowVersion`）。
  语义上："事件行的定长列 = 精确写入值；变长列在其行版本未被取代时精确、
  被取代后为 NULL（消费方按主键重取）"。扫描在根锁内进行，版本判定与池
  读取对写路径原子（网络/嵌入两路共用同一解码面）。
  备选（推迟池块回收至环丢弃 / 变长字节内嵌 WAL 载荷）因内存无界与恢复
  面改造代价被否；如后续需要"历史变长值订阅"，应走 WAL 载荷自包含化。
- **C ABI**：v2 只增符号（订阅族）；`RTDB_ABI_VER` 随能力递增为 2（既有
  v1 符号语义/签名未变），`scripts/cabi_smoke.py` 期望值同步。
- **等值提交唤醒**：`MarkCommitted` 侧统一 `WakeAll32`（futex/WaitOnAddress
  等待字 = committed_seq 低 32 位）；WaitOnAddress/futex 跨进程生效，故
  单写者与多写者嵌入场景均不依赖轮询（超时参数仍为服务端兜底）。
- **测试证据**：`TestScanRange*`（回绕/窗口/回调停止/预算截断/撕裂尾/溢出
  判据）+ `TestSubscribe*`（三事件内容、过滤、批原子边界、超时空批、溢出重
  同步、并发写无丢失/无重复、扩展列、变长列版本门、拒绝面）+ `CAbiTest.
  SubscribeCursorNextDeliversEvents`；全量 202/202 通过（W1 后新增 15 用例）。

### W3 落地记录（rtdbd 服务端）

- **交付面**：`rtdbserver`（STATIC：`src/server/{config,server}.cpp`）与
  `rtdbd`（EXE：`src/server/main.cpp`；§4 计划名 `rtdb_server_core` 收敛为
  `rtdbserver`）。核心新增：`src/infra/sha256.{hpp,cpp}`（SHA-256 自实现，
  零依赖；AUTH 摘要，双端/测试共用）、`Engine::DescribeTable`（句柄可见列
  schema 快照，持根锁与在线加列互斥）、`Engine::{RefreshWriterHeartbeat,
  WriterHeartbeatNs}`（心跳写/读对）、`net::ReadValueGeneric`（自描述值
  解码，变更事件与 W4 客户端共用）。
- **AUTH 摘要口径（相对 docs/04 §5 的差异）**：请求 = `[Str user]
  [Var 32B digest]`，digest = `SHA-256(auth_salt || password)`；盐为部署侧
  共享配置（服务端 `auth_salt`，客户端连接参数），**不走线上**——docs/04
  的"AUTH 线上传 salt"表述作废（盐是部署常量，线上传省带宽且语义等价）。
  `rtdbd --hash-password <pw> [--salt <s>]` 离线生成摘要 hex；等时比较
  （用户不存在也走定长比较）。
- **会话号（D6 调整）**：由 128-bit 收敛为 **u32 随机号 + 连接绑定**（帧头
  session 即 32 位；服务端以连接私有状态校验回显，不设全局会话表）。TTL
  滚动续期（`session_ttl_ms`，默认 30min）：过期 → 502，须重新 AUTH；
  重新 AUTH 自动重建订阅/分页。
- **协议布局（W3 as-built；全小端；请求体=功能载荷，应答 = `[i16 err]` +
  成功体 / 失败 `[u16 msg_len][UTF-8 msg]`）**：
  - AUTH(1)：`[Str user][Var digest]` → `[u32 session_id][u32 ttl_ms]`；
    口令错 501（不断连可重试）。
  - PING(2)：空 → `[i64 committed_seq][u64 writer_heartbeat_ns]
    [i64 checkpoint_seq][u32 ttl_ms]`。
  - DDL(10)：`[u8 sub]`——CREATE=1 `WriteTableDef` →
    `[i64 table_id][u32 visible_cols][u32 layout_ver]`；DROP=2 `[Str name]`
    → 空；DESCRIBE=3 `[Str name]` → `[i64 table_id][u32 layout_ver][结果头
    (名/列/行数0)]`；未知 sub → 403。
  - EXEC_BATCH(11)：`[u8 mode]`——0=`[u32 n][逐 op: u8 type(1/2/3) +
    Str table + 行值或主键]`（update=整行且 row0=原主键；delete=仅主键）→
    `[i64 committed_seq]`；1=`WriteBlock` → `[i64 committed_seq]`。服务端
    按表名映射 schema（同请求内缓存）；批原子语义由引擎保证，错误码透传。
  - SCAN(12)：`[Str table][u8 has_lo][tag+i64][u8 has_hi][tag+i64]` →
    结果头（自描述）+ 逐行值。
  - SCAN_PAGE(13)：OPEN=0 `[Str table][u32 page_rows]` →
    `[u64 page_id][u8 done][结果头][行...]`；FETCH=1 `[u64 page_id]` →
    `[u8 done][u32 n_rows][行...]`；CLOSE=2 `[u64 page_id]` → 空（幂等）；
    未知句柄 → 102。实现=每页全扫后切片 + 主键续扫（开区间）；done=1 后
    仍可重复取（0 行 + done=1）。
  - SUBSCRIBE(20)：`[u32 n][Str 表名 ×n]`（n=0=全部活跃表）→
    `[u32 sub_id][i64 start_seq]`；重复订阅=替换旧游标；表不存在/Reader →
    303/105。
  - FETCH_DELTA(21)：`[u32 sub_id][u64 from_seq][u32 timeout_ms]
    [u32 max_bytes]` → `[i64 last_seq][u32 n][变更...]`；变更 =
    `[u8 op][i64 table_id][Str table][u64 seq][u64 ts_ns][u64 row_no]
    [u64 row_ver]` + insert/update `[u32 nvals][自描述值...]` / delete
    `[自描述键值]`。`from_seq` 越窗 → 402；timeout 受 `delta_max_timeout_ms`
    上限约束、内部 ≤250ms 切片（保 stop 响应性，语义=预算内等待首批）；
    max_bytes 按"至少 1 条"截断，`last_seq`=最后被编码条目的 seq（客户端
    据此续拉无缺漏）；单条超帧上限 → 306。
  - ACK(22)：`[u32 sub_id][u64 seq]` → 空（诊断账本，M3 不影响交付）；
    UNREGISTER(23)：空载或 `[u32 sub_id]` → 空（清订阅）。
- **错误路由**：未知功能号 → 400（不断连）；载荷畸形/未读尽/未知子操作 →
  403（不断连）；帧 CRC/magic/版本/压缩位/超上限、请求帧携带应答位 →
  关连接；超会话上限 → accept 后限时读一帧回 404 再关；口令错 501；
  会话 0/失配/过期 502。
- **优雅退出（D7）**：Stop = stop 标志 → join accept（≤100ms 轮询）/心跳
  线程 → 等全部会话线程收敛（recv 250ms 轮询；FETCH_DELTA ≤250ms 切片；
  收敛预算 = `timeout_ms`，默认 30s）→（可选）终场冷快照 → 引擎析构
  （组提交终刷）。极端不收敛时引擎**故意泄漏**（防 UAF，进程退出统一回收）
  并记录 `last_error`；`main.cpp` 处理 SIGINT/SIGTERM（Windows 控制台
  事件），并提供 `--exit-after-ms`（脚本/烟测用，优雅退出码 0）。
- **配置面**：`key = value` 文本（`#` 注释；**未知键拒绝**防拼写漂移）：
  `instance/path/listen/size_mb/fsync/auth_salt/user(<名> <64hex>，可多行)/
  session_ttl_ms/max_sessions/max_payload_kb/heartbeat_ms/snapshot_on_exit/

- **验收证据**：`tests/unit/test_server.cpp` 15 用例——认证（口令错/未认证/

### W4 落地记录（rtdb_client）

- **交付面**：`rtdbclient` 库（`include/rtdb/rtdb_client.hpp`、`include/rtdb/
  rtdb_client_c.h`、`src/client/{rtdb_client.cpp,client_c_abi.cpp}`）+ 示例

- **请求面与重试边界（重要语义，docs/13 §3-D2 收口）**：
  - 读类（PING/DESCRIBE/SCAN/SCAN_PAGE）网络错误 → 自动重连 + AUTH 后**重发
    一次**（读幂等）；
  - 写类（CREATE/DROP/EXEC_BATCH/块 UPSERT）**不自动重发**——防"服务端已
    提交、应答丢失"的重复写；调用方按需自建幂等键重试；
  - 会话失效 502 → 重 AUTH 后**任何请求**重发一次（该请求必未执行，无重复
    风险）；
  - 帧层异常（CRC/版本/超限/半帧）一律归 `kNetworkError` 并丢弃连接，绝不
    在可疑流上重试。
  - `Client::Connect` 校验 port≠0、user 非空 → 101；AUTH 摘要 =
    `SHA-256(auth_salt || password)`（`infra::Sha256Concat`，`sha256.hpp` 以
    `RTDB_API` 导出，rtdbclient 直接链接 rtdbcore 复用，不重复编译）。
- **订阅模型（每订阅 = 独立连接 + 泵线程，FETCH_DELTA 长轮询）**：
  - 续传点 = **最后交付事件的 seq**：回调返回后才推进；回调异常则不推进
    → 重投（允许重复、不允许缺漏）；ACK 每非空批"尽力发"（诊断账本，失败
    忽略）；位置读写/`ResetTo` 经 `shared_ptr<Impl>` 内互斥与 CV 同步。
  - 溢出 402 → `on_overflow(Subscription&)` → 泵挂起等待 `ResetTo`（epoch
    判据，100ms 周期检查 stop）；典型处置 = 整表 SCAN 重取 + `ResetTo(重取
    时水位)`（示例与测试均为该路径）。
  - 重连指数退避 `reconnect_min_ms=200`→`reconnect_max_ms=5000`；首连以
    SUBSCRIBE 返回 `start_seq` 为起点，**重连不覆盖**（续传不变）；表不存在
    等订阅校验失败按退避重试（可先订阅后建表）。
  - 生命周期：`shared_ptr<Impl>` 保活——回调线程内调 `Close()` 仅置停并
    返回（不 join），泵自行退出后释放；`Close()` join 上界 = 泵单次阻塞窗口
    （长轮询 ≤ `delta_wait_ms`、连接 ≤ `connect_timeout_ms`）；不调
    `TcpSocket::Shutdown` 避免关闭竞态。
  - `SubscriptionOptions`：`tables/on_change/on_overflow/on_state/
    delta_wait_ms=1000/delta_max_bytes=1MiB/reconnect_min_ms/reconnect_max_ms`。
- **落地修复（demo 暴露）**：泵最初在每轮 FETCH 成功后误走"重连"路径——每次
  交付都新建连接（5s 内 26 连接/26 次 AUTH）。`Run()` 改为 `linked` 状态机：
  连接成功即保持，仅错误路径丢弃重连（溢出路径保留连接）；修复后 demo
  统计 = 2 连接（请求面 + 订阅面）/55 请求，事件逐条有序交付。
- **C ABI 精简面（`rtdb_client_c.h`，只增符号）**：`connect/close/ping/
  create_table/drop_table/upsert_block（列式块）/scan/free_rows` + 订阅族
  `sub_close/sub_position/sub_reset`；复用 `rtdb_cabi.h` 的 `rtdb_value/
  rtdb_column_def/rtdb_rows/rtdb_change`。行结果内存 = 单块分配
  `[RowsHeader{owner*}][rtdb_row 数组]`，`free_rows` 经首行回退取 owner 一次性
  释放（可重入调用、NULL 安全）；`rtdb_change` 为**栈上物化**结构，仅在回调
  期间有效。兼容性补丁：`rtdb_cabi.h` 的 `RTDB_CHG_*` 加 `#ifndef` 保护，

- **测试证据**：`tests/unit/test_client.cpp` 9 用例——连接/认证（口令错 501、

  position）、先订阅后建表（退避重试）、**断连续传**（Stop→原端口重启：
