## 1. M2 范围界定

| 维度 | 内容 |
|---|---|
| 目标（docs/05 §3） | NativeApi 收敛、CAbi、RecordBlock 批量、Result 体系；周期约 3 周 |
| 出口标准 | ① 《04》示例程序原样跑通；② bench 嵌入模式达标（docs/05 §4） |
| 覆盖率门禁 | 维持 M1 水平：engine/ 与 storage/ ≥ 85%（全局 ≥ 80%） |

M2 的定位是"接口"：M1 交付了引擎能力但 API 形态是演进式的（Engine 静态方法 +
`std::vector<ColumnValue>` 行式入参），M2 以 docs/04 规范为基准**收敛公共面**——
伞头/Options/TableDef/Row/Upsert 便利面对齐规范表述，列式 RecordBlock 打开百万行/s
批量入口，C ABI 冻结符号提供跨语言绑定基座。**引擎内核语义不变**（M1 的 WAL/组提交/
恢复/快照全部保留，RecordBlock 走同一条组提交管线）。

## 2. 核心技术决策

### M2-D1 NativeApi 收敛（docs/04 §1~§3 对齐，W1）

现状与 docs/04 的差距逐项处置：

| # | docs/04 规范 | M1 现状 | M2 决策 |
|---|---|---|---|
| 1 | `#include <rtdb/rtdb.hpp>` 伞头 | 无伞头，逐头包含 | 新建 `include/rtdb/rtdb.hpp`（C++ 公共头一键包含；C 头 `rtdb_cabi.h` 不进伞头） |
| 2 | `Options{instance, role, path, wal_fsync}` | `instance_name/file_path/fsync` | 字段改名对齐规范（库未发行、无外部用户，直接改；`initial_size_bytes` 保留为可选字段） |
| 3 | `TableDef{name, columns, primary_key, secondary, max_rows_hint}` | `name/row_cap/columns(vector)`，主键隐式列 0 | `columns` **保持 `std::vector<ColumnDef>`**（113 用例均 `push_back` 形态，span 化迁移成本高而收益低；docs/04 §3 示例同步改写为 vector 形态并记录决策）；新增 `primary_key`（`vector<string_view>`，空=列 0 隐式主键，与 M1 语义一致；多列暂返回 kUnsupported）、`secondary`（`vector<IndexDef>`，建表直建二级索引的便利面，旧 `CreateSecondaryIndex` 保留）、`max_rows_hint`（0=默认；超 `kMaxRowCap` 或行数据区超 `kMaxRowDataBytes(64KB)` 返回 kLimitExceeded，见 M2-D5）；变长列 len 须为 0（docs/04 §3 的 `String,64` 长度上限语义列入复评清单） |
| 4 | `RTDB_ASSIGN_OR_MOVE` / `RTDB_CHECK` | 仅 `RTDB_TRY_OR_RETURN` | `result.hpp` 增两个规范宏（内部 `RTDB_TRY_OR_RETURN` 保留为别名，不破坏存量调用）；`Result<T>` 增 `operator*`/`operator->`（支撑 `auto tbl = *eng.OpenTable(...)` 写法） |
| 5 | `tbl.Upsert(rtdb::Row{{"id", int64_t{42}}, …})` | `Engine::Insert(table, vector<ColumnValue>)` | 新增面：`ColumnValue` 增 public 隐式构造（int64_t/double/bool/const char*/string_view → 对应标量/变长类型）；`Row = vector<pair<string_view, ColumnValue>>`（按列名定位的部分行，未提供列走默认值/NULL，同 M1 旧句柄窄行语义）；`TableHandle` 增非拥有 `Engine*` 成员支撑 `Upsert/Get/Delete` 成员函数（句柄可拷贝、不拥有引擎；M1 的 Engine 静态方法全部保留） |
| 6 | `eng.Subscribe({"measure"})` | 无 | **M3**（docs/05 §3 订阅归 M3；docs/04 §3 示例的订阅段在 M2 示例中注释标注，不做占位实现） |

upsert 语义（规范 §3 "单条 upsert"）：存在则整行覆盖、不存在则插入；与 M1 `Insert`
的"冲突即 kAlreadyExists"并存为不同原语，旧 API 语义不动。

### M2-D2 RecordBlock 列式批量（src/storage/record_block.*，W2）

docs/03 §2.3 `Result<uint64> UpsertBatch(RecordBlockView)` 的落地设计：

- **宿主侧双层类型**：`RecordBlock`（构建器，拥有列缓冲）+ `RecordBlockView`（零拷贝
  视图，引擎入参）。`RecordBlock::AppendColumn(name, span<const T>)` 链式调用
  （docs/04 §3 原样）：定长列 `span<const int64_t>/<const double>/<const uint8_t>`
  （bool/unix_ts 走 int64 位模式）；变长列 `span<const std::string_view>`；每列可带
  null 掩码 `span<const uint8_t>`（1B/行，bit 或字节布码——取字节布码，简单优先）。
  行数取各列长度一致（不一致 kInvalidArgument），未追加的列走默认值/NULL；
- **引擎路径零中介**：`Engine::UpsertBatch(RecordBlockView) → Result<uint64_t>`
  （返回 committed_seq）。**不经 `ColumnValue` 逐行构造**（M1 `ExecuteBatch` 的
  行式路径每行一个 vector，百万行/s 的关键就在跳过它）：table_store 暂存阶段直接
  从列式内存按 schema 编码校验+预留，ApplyStaged 逐行落槽——W4 的两段式结构
  （Stage 零副作用先行 / Apply 统一应用）原样复用，仅数据源换成列式缓冲；
- **原子性**：整块一个 `BATCH_BEGIN + N×op + BATCH_COMMIT`（复用组提交）；逐行按
  实际存在性记 kInsert/kUpdate（upsert 语义），恢复幂等由 row_no+row_ver 保证
  （M1 重放器零改动）；任一行校验失败整批零副作用；WAL/应用阶段失败毒化
  （kPoisoned，同 ExecuteBatch 契约）；
- **崩溃注入点**：`block.apply.mid`（块中行应用一半）、`block.commit.before`
  （COMMIT 落环前）两个新注入点，随 W4/W5 的九点矩阵进混沌脚本；
- **变长列边界**：RecordBlock 的变列入参经 `string_view` span 零拷贝进暂存，
  再拷入映像变长池（与 M1 行式路径同一池，无第二实现）。

### M2-D3 C ABI 面（src/api/c_abi.cpp，W3）

docs/04 §4 的落地设计：

- **新目录 `src/api/`**（docs/02 §6 `api/(native_api,c_abi)` 规划）：native 面继续
  由 `src/engine.cpp` 承载（同 M1 对 `src/engine/` 目录的收敛决策，不为单文件编
  目录），`src/api/c_abi.cpp` 承载 C 面——纯 `extern "C"` 导出，`RTDB_API` 宏
  保证 Windows dllexport；
- **符号冻结语义**：`RTDB_ABI_VERSION` 0 → **1**（version.hpp）；符号前缀
  `rtdb_abi_`；函数集：`rtdb_abi_version` / `rtdb_abi_open` / `rtdb_abi_close` /
  `rtdb_abi_create_table` / `rtdb_abi_drop_table` / `rtdb_abi_open_table` /
  `rtdb_abi_insert`（行式）/ `rtdb_abi_upsert_block`（列式，docs/04 §4
  `rtdb_abi_exec_batch` 的落定形态）/ `rtdb_abi_get` / `rtdb_abi_scan` /
  `rtdb_abi_committed_seq`。订阅族 `rtdb_abi_subscribe` 等归 M3；
- **头文件单独发行**：`include/rtdb/rtdb_cabi.h`——纯 C（`extern "C"` 守卫）、
  仅用定长类型与不透明 `void*` 句柄、错误码 `int32_t` 与 `Err` 一一对应
  （文档注释映射表）；可被 Python ctypes / JNI 等其他语言直接包含（"绑定基座"）；
- **内存约定**：入参为调用方内存、函数内即刻消费（拷入映像或解码进 Result），
  不同步回写；出参 buffer 由调用方提供（`rtdb_abi_get` 的 vals 数组 + 容量
  入出参）；句柄角色校验（Reader 拒写返回 kReadOnlyHandle）；
- **偏离记录**：docs/04 §4 `rtdb_abi_open` 四参签名未含 fsync 档位——M2 增补
  `wal_fsync` 参数（打开时确定组提交档位，比 open 后 setter 更可靠），头注释注明。

### M2-D4 bench 嵌入模式（W2/W3）

docs/05 §4 的 M2 相关行：`RecordBlock 批量 upsert ≥ 1,000,000 行/s（8 列混合类型）`。
M1 已有 `--rtdb-bench`（W6 量级确认五项）；M2 扩展列式块场景。**块大小受
M1 行数据区约束**：`rec_fixed_len × row_cap ≤ kMaxRowDataBytes(64KB)`
（docs/09 §7"单表行数据 ≤64KB"行，段目录化复评项）——8 列混合（约 72B/行）
的可行 row_cap ≈ 910，故 bench 取 **512 行 × 8 列混合块循环 upsert**
（首轮插入、后续轮合并路径）测稳态吞吐。口径：总行数/墙钟（含 WAL 落环，
per_second 档）。既有五项不回归。

### M2-D5 段目录化复评（行槽 >8192，W3 收尾）

docs/09 §7 顺延项之一。`kMaxRowCap=8192` 的根源：版本数组 = row_cap×8B 须容身
单次 slab 分配（≤64KB）；docs/04 §2 `max_rows_hint` 注释的"段按需扩展"即段目录化。
工程量评估：行寻址 + 版本数组 + 墓碑位图布局重写，牵连 table_store/wal 重放/
快照拷贝，估 2 周+。**M2 结论预置：不复选入主线**（与 doublewrite/compact 一并
复评并记录数据依据），M2 内 `max_rows_hint` 超限返回 kLimitExceeded（docs/04 §3
示例的 1000000 改写为 8000 并注释上限原因）。

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| `kMaxRowCap=8192` 限制 max_rows_hint 语义（docs/04 100 万提示） | 高 | M2-D5：段目录化复评挡在主线外，超限明确 kLimitExceeded + 文档记录；示例用 8000 |
| ColumnValue 隐式构造引入重载歧义（bool vs 整型/浮点） | 中 | bool 单列重载优先；构造集最小化（int64_t/double/bool/const char*/string_view 五枚）；聚合初始化冲突用例随 W1 交付 |
| TableHandle 持 Engine* 的生命周期悬垂 | 中 | 文档明示"句柄不拥有引擎"；无效/悬垂句柄走 kTableNotFound/kInvalidArgument 校验（table_id/desc_off 令牌校验已有）；不提供跨 Engine 传递测试之外的场景 |
| RecordBlock 百万行/s 不达（WAL 落环成为瓶颈） | 中 | 列式路径跳过 ColumnValue 是主杠杆；组提交聚合本就一次落盘确认；W2 周内 bench 不达标则先查暂存段拷贝（视图→Stage 应零拷贝），再议块内多批切分 |
| C ABI 句柄角色/线程语义与 C++ 面漂移 | 中 | c_abi.cpp 仅做薄封装（参数解码→调 Engine→错误码映射），无独立状态机；ctypes 冒烟与 test_cabi 双通道覆盖 |
| C/C++ 混合构建（CMake project LANGUAGES） | 低 | `project(... LANGUAGES CXX C)`；cabi_demo 独立目标仅链 rtdbcore，不碰测试目标 |
| docs/04 §3 示例含订阅段（M3 能力） | 低 | 示例程序中订阅段注释标注 M3；docs/04 §3 旁注"订阅族归 M3（docs/05 §3）" |
