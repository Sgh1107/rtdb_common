# 01 开发总体方案

## 1. 项目目标

### 1.1 产品定位
一个**通用高性能内存实时数据库内核**：
- 任何宿主软件可在**进程内嵌入**使用（加载动态库后直接读写本机共享内存区，微秒级延迟、无 IPC）；
- 也支持作为**独立服务**跨机网络访问；
- 表结构、数据类型、索引、权限均为通用语义，**不含任何行业业务概念**。

### 1.2 与老 PSRtdb 的关系
| 维度 | 老 PSRtdb | rtdb_common |
|---|---|---|
| 业务耦合 | 硬编码 analog/status/设备表名、组态变量 $$SysGrp | 零业务语义 |
| 关系库 | 强绑 Oracle/Sybase/MySQL 双向同步 | RDB 为可选插件适配器 |
| 宿主形态 | MFC exe + DLL 绑死 VS2013 | 纯 C++17 库 + 守护进程，CMake 跨平台 |
| 变化感知 | 秒级时间戳轮询 | 每记录版本号 + ChangeLog 游标（纳秒级单调序列） |
| 并发 | 每表 1 把跨进程锁 | 表级 RWLock + 记录级乐观读（版本号校验） |
| schema | 定长结构体硬编码，改结构全量重建 | 版本化柔性布局，支持在线加列 |
| SQL | 手写单表子集 | 保留单表子集起步，解析器独立成模块 |
| 扩展容量 | 1800 表 / 8 索引 / 6 键列上限硬编码 | 配置化上限，注册区按需扩展段 |

### 1.3 成功标准
1. 本机进程内单测点读写 P99 < 10μs；批量 10 万点/秒写入无丢失；
2. 断电重启后数据自动恢复（WAL + 快照）；
3. 第三方 C++ 程序 ≤ 30 行代码完成建表→写入→订阅全过程；
4. Windows/Linux 同一代码库编译通过，字节序互通。

## 2. 技术选型（全部落在 C++17 能力圈内）

| 领域 | 选型 | 说明 |
|---|---|---|
| 语言 | C++17（最低 C++14 编译容忍） | `std::optional/variant/string_view/shared_mutex/atomic/pmr::monotonic_buffer_resource` 均为 C++17；**禁止** C++20 特性 |
| 构建 | CMake ≥ 3.16 | 输出静态库+动态库+可执行文件；预设 MSVC/gcc/clang 工具链 |
| 共享内存 | Win: `CreateFileMappingW/MapViewOfFile`; Linux: `shm_open/mmap` | 统一封装在 `ShmRegion` 抽象层 |
| 跨进程等待 | Win: 命名事件+SRWLock 语义; Linux: futex 化的命名信号量 | 封装 `IPCXLock/IPCSema`；优先自旋+退避，减少系统调用 |
| 时间 | `std::chrono::steady_clock/system_clock` | 内部统一 int64 纳秒 |
| 日志 | 自研轻量异步日志（环形缓冲）或 fmt 风格格式化 | fmt 若引入则仅头文件模式且可选 |
| 测试 | GoogleTest（仅构建 test 时拉取）+ 自研压测工具 | |
| RPC | 自研二进制协议 over TCP（epoll/IOCP 各自实现，统一接口 `INetTransport`） | 协议沿用老系统"功能号+多缓冲"思路但带长度前缀帧和会话鉴权 |

### 2.1 明确不做的事（防范围蔓延）
- 不做磁盘关系型完整 SQL 方言、不做优化器代价模型（首期）；
- 不做分布式共识/Paxos——集群复制采用主备 ChangeLog 异步流；
- 不内置任何 UI（老的 MFC 壳彻底抛弃）；
- 不兼容老共享内存数据格式（提供一次性离线迁移工具，见交付清单）。

## 3. 总体里程碑概览

| 阶段 | 内容 | 出口标志 |
|---|---|---|
| M0 地基 | shm 管理、B+树、IPC 锁、日志、错误码体系、CI 骨架 | 单元测试通过；demo 进程间同页内存互斥成功 |
| M1 引擎 | 存储引擎、元数据目录、索引维护、WAL/快照恢复 | 建表/CRUD/崩溃恢复全链路测试通过 |
| M2 接口 | 原生 C++ API 收敛、C ABI、批量协议 | 性能基线达标；示例程序跑通 |
| M3 服务 | rtdbd 守护进程（RPC+订阅推送）、客户端连接库 | 双机演示：写主机→备机订阅收到增量 |
| M4 完善 | SQL 单表子集、权限、监控计数器、迁移工具、文档 SDK | 见《05 交付清单》验收项 |

详细排期与人力估算见《05 交付清单与里程碑计划》。

## 4. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 共享内存布局升级破坏存量数据 | 已部署场景数据不可用 | 所有头部结构带 magic+version+layout_crc；不匹配时只读打开并提示迁移 |
| 跨进程锁在两平台的语义差异 | 死锁/丢通知 | 抽象层先写协议文档再实现；用混沌测试反复 kill -9 验证 |
| 写入吞吐与 WAL 刷盘竞争 | 吞吐骤降 | 组提交（group commit）+ 可配置 fsync 策略（always/per-second/never） |
| B+树节点放 shm 导致对齐问题（32/64 位混部） | 访问违例 | 节点定长 + 显式 offset 寻址（禁裸指针入内存），启动时校验指针宽度宏 |
| 老系统使用者习惯 string/char* 接口 | 迁移成本 | C ABI 提供定长 char 数组的经典风格包装层，与现代 API 并存 |
