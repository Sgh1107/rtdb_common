# C3 布局与协议规范 v1

> 适用：M4（docs/16 D10/D11）。本文描述**共享内存（shm）磁盘/映射布局**与
> **网络帧协议 v1** 的线上格式与兼容纪律，供运维、跨语言绑定、升级迁移与
> 故障排查引用。所有常量取自 `include/rtdb/version.hpp`、`include/rtdb/proto_v1.h`、
> `src/infra/layout.hpp`、`src/infra/shm_region.cpp`、`src/storage/wal_ring.{hpp,cpp}`、
> `src/net/{wire.hpp,codec.hpp,value_codec.hpp}`、`src/server/config.*`；不臆造数值。
>
> **标记约定**：`[待实测]` = 需标准 CI/双机/CRC 互操作复核；`[待评审]` = 需在 M4
> 收口评审确认的口径或不一致项。协议版本仍为 **v1（数字只增不改）**。

## 1. 版本纪律总览（docs/16 D11）

| 项 | 值/纪律 |
|---|---|
| 协议版本 | `RTDB_PROTO_VERSION = 1`；func/子码/标签/错误码一律追加到尾部语义段，既有数值不改 |
| C ABI | `RTDB_ABI_VER = 2`（`rtdb_cabi.h`）/`RTDB_ABI_VERSION = 2`（`version.hpp`），`static_assert` 单一真源；**M4 冻结，不新增符号、不改签名** |
| shm 布局 | `kShmFormatVersion = 2`（`version.hpp`）；**M4 不升级**，PerfCounters 走 host 原子计数 + ADMIN/STATS RPC，不动 SuperBlock |
| 版本串 | `RTDB_VERSION_MAJOR=0 / MINOR=2 / PATCH=0`、`kVersionString="0.2.0"`（M4 收口已推进，宏与字符串对齐；D11 原文「0→1」为笔误，见 §7） |
| 兼容性 | M3 客户端 ↔ M4 服务端、M4 客户端 ↔ M3 服务端双向可用（§6）；新 func 对旧服务端降级 `kNotImplemented=400` |

> 布局变更铁律（`version.hpp` 注释）：任何破坏存量映像可读性的布局改动**必须递增
> `kShmFormatVersion`**，并在迁移工具（`tools/migrate_from_psrtdb`）中提供升级路径；
> 稳定字段顺序/增删同步 `RefreshLayoutCrc`。详见 §7。

## 2. shm 布局：4096B SuperBlock

### 2.1 头部保留区与固定分区（`src/infra/layout.hpp`）

| 常量 | 值 | 含义 |
|---|---|---|
| `kShmMagic` | `0x52544442434D4E31ULL` | `"RTDBCMN1"` 的小端内存表示 |
| `kHeaderReservedBytes` | `4096` | SuperBlock 所在区；`static_assert(sizeof(shm_SuperBlock)==4096)` |
| `kAllocCtlOffset` / `kAllocCtlBytes` | `4096` / `512` | 分配器控制块 |
| `kRootMutexOffset` / `kRootMutexBytes` | `4608` / `64` | 根互斥锁状态字 |
| `kDataStartOffset` | `8192` | 可分配数据区起始（页对齐） |

`shm_SuperBlock` 为 **standard-layout、定长、无虚函数/裸指针**；共 14 个 8 字节字段 +
6 个 4 字节字段 = 136B，尾部 `char reserved[4096 - 14*8 - 6*4]`（3960B）补齐至 4096B。

### 2.2 稳定字段（参与 `layout_crc`，创建时定格）

| 字段 | 类型 | 说明 |
|---|---|---|
| `magic` | u64 | `kShmMagic` |
| `format_version` | u32 | `kShmFormatVersion`（当前 2） |
| `header_size` | u32 | `sizeof(shm_SuperBlock)`，防结构膨胀错读 |
| `pointer_width` | u32 | `sizeof(void*)`，拦截跨字宽误挂载 |
| `layout_crc` | u32 | 稳定字段区 CRC32（计算时自身按 0 计） |
| `created_unix_ns` | i64 | 映像创建时间（Unix 纳秒） |
| `max_size_bytes` | u64 | 映像总容量 |
| `wal_ring_off` / `wal_ring_bytes` | u64 | WalRing 区偏移/容量（含环头）；0 = 尚未布局 |
| `catalog_desc_off` | u64 | 目录描述符数组区偏移；0 = 尚未布局 |
| `max_tables` / `max_cols_per_table` / `max_indexes_per_table` | u64 | 默认 `65535 / 128 / 16`（`InitSuperBlock`） |

**CRC32 自校验**（`src/infra/shm_region.cpp`）：稳定字段区 = 从结构体起始到
`max_indexes_per_table` 结束（`kStableFieldsBytes = offsetof(...)+sizeof(u64)`，
即 88B）。`RefreshLayoutCrc` 把该前缀拷入零初始化快照、将快照内 `layout_crc` 置 0，
对 88B 求 `Crc32` 写回 `sb->layout_crc`；`ValidateSuperBlock` 以同法复算比对。

### 2.3 挂载校验与运行时字段

`ShmRegion::Open`（`shm_region.cpp`）：仅比较**稳定字段前缀**是否全零（不整块
`memcmp`，避免与运行时字段的原子写构成 TSan 数据竞争）；全零 → `InitSuperBlock`
新建并 `Flush`，否则 → `ValidateSuperBlock`：

| 判据 | 返回码 |
|---|---|
| `magic != kShmMagic` | `kBadSuperBlock=201` |
| `format_version != kShmFormatVersion` | `kVersionMismatch=202` |
| `pointer_width != sizeof(void*)` 或 `header_size` 不符或 CRC 不符 | `kIncompatibleLayout=203` |

新建/损坏拒绝静默重建覆盖既有数据。运行时字段（**不参与 CRC**）：

| 字段 | 类型 | 语义 |
|---|---|---|
| `committed_seq` | u64 | 已提交变更全局最大单调序号（订阅游标基准） |
| `checkpoint_seq` | u64 | 重放下界：已随快照/强刷落盘、环内该点之前记录已回收 |
| `flushed_seq` | u64 | 后台节流 flush 覆盖水位；断电丢失窗口 `(flushed_seq, committed_seq]` |
| `writer_heartbeat_ns` | u64 | 主写者心跳（Unix 纳秒）；`RefreshWriterHeartbeat()` 刷新 |
| `session_count` | i64 | 成功 `Open` 累计次数；**仅写侧角色**在分配器 `Attach` 成功后 `fetch_add(1)`（P2-3 下移，Attach 失败不虚增）；Reader 只读映射不推进 |
| `role_flags` / `fsync_policy` | u32 | 角色位标志 / 持久化档位 |

64 位运行时字段以 `AsAtomicI64/AsAtomicU64`（`reinterpret_cast` 到等宽 `std::atomic`，
C++17 无 `atomic_ref` 的惯用法）读写；`static_assert(sizeof(std::atomic<int64_t>)==8)`
要求平台无锁 64 位原子。

## 3. 变长池 / Slab / 目录双 B+ 树 / 行槽与墓碑

| 组件 | 落地（docs/03 §2/§3/§4） |
|---|---|
| `SlabShmAllocator` | 分级 slab `32B<<i` 共 `kSlabClassCount=12` 级、最大 `kMaxAllocBytes=64KB` + 空闲链表（`shm_AllocCtl`）；块头自描述；`Allocate/Deallocate(uint64 off)`；`ReservePermanent` 用于 >64KB 的 WAL 环永久预留（4KB 对齐、映像生命周期内不归还） |
| `MVarLenPool` | 变长列专用池（最佳适配 + 分裂合并），返回 `pool_off+len`；变长列在记录内仅存 8B `(u32 off, u32 len)` 槽 |
| 目录双 B+ 树 | `infra::SharedBTree<K,P>` 模板（`src/infra/shared_btree.hpp`），节点定长 4KB、全部 offset 寻址；as-built 别名在 `src/storage/catalog.hpp`：`CatalogNameTree = SharedBTree<kMaxTableNameBytes,uint64_t>`（名→table_id）、`CatalogIdTree = SharedBTree<8,uint64_t>`；docs/03 §2.2 的设计稿别名 `StringBTree/IntBTree` 与之对应。建/删/改表由目录事务保护，持久化于映像内 |
| 行槽 | `rec_ptr = data_base + row_no * rec_fixed_len`，O(1) 寻址；记录布局 `[列0..N-1][null 位图]`（`(col_count+7)/8` 字节），整体 8B 对齐——空值与空串可区分 |
| 墓碑 | 删除 = 墓碑位置位 + 摘除索引键，行槽**保留供覆盖复用**；版本单调 +2、暂存槽互斥、失败恢复墓碑（P0-3 行槽复用）；完整 compact/离线 GC 归 M5 |

上限由 SuperBlock 稳定字段配置化（`max_tables/max_cols_per_table/max_indexes_per_table`），
不再硬编码。

## 4. WAL 环（`src/storage/wal_ring.{hpp,cpp}`）

### 4.1 物理结构与环头

单次 Slab 分配，偏移写入 `SuperBlock.wal_ring_off/wal_ring_bytes`：
```
[shm_WalRingHeader 64B][记录区 area_bytes]  ← 变长记录顺序写，写满回绕
```
环头（64B，standard-layout，`sizeof==64` 断言）：`magic(kWalRingMagic=
0x5254444257414C31ULL "RTDBWAL1")`、`area_bytes`、`head_seq`（下一待分配 seq，从 1 起）、
`tail_seq`（最老保留记录 seq，空环 = head_seq）、`head_pos/tail_pos`（记录区内偏移）、
`poisoned(u32)`、`reserved0(u32)`、`reserved[1](u64)`。`poisoned` 走 `AsAtomicU32`
原子视角（写线程置位、业务线程无根锁读取，避免 TSan 数据竞争）。

### 4.2 记录线格式（D3 铁律：逐字段小端显式编码，禁止整 struct 落盘）

```
[0]  u32 total_len      整条记录字节数（含 CRC）
[4]  u32 payload_len
[8]  u64 seq            pad 记录恒为 0
[16] u64 ts_ns          Unix 纳秒
[24] u64 row_no
[32] u64 row_ver        幂等重放判重依据
[40] i64 table_id
[48] u8  op
[49] u8  flags          预留（恒 0）
[50] u16 reserved
[52] u32 reserved2
[56] payload[payload_len]
[total_len-4] u32 crc   Crc32(记录首部至 CRC 前)
```
**56B 定长头 + 载荷 + 4B CRC**，逐字节紧排不做对齐填充；`kWalRecHdrBytes=56`、
`kWalRecCrcBytes=4`、`kWalMinRecordBytes=60`（56+0+4，docs/08 的"16B 头"落地为 56B）。
小端编解码 helper：`EncodeU32LE/EncodeU64LE/DecodeU32LE/DecodeU64LE`。

`WalOp`（持久化取值，只增不改）：`kWalOpInsert=1 / Update=2 / Delete=3 /
BatchBegin=4 / BatchCommit=5 / CreateTable=6 / DropTable=7 / **Pad=0xFF**`。

### 4.3 容量可配（`wal_ring_kb` / `wal_ring_bytes`）

| 常量/字段 | 值 |
|---|---|
| `kDefaultWalRingBytes` | `64*1024`（恰为 slab 最大级 64KB） |
| `kMinWalAreaBytes` | `4096`；`kMinWalRingBytes = 64 + 4096 = 4160` |
| `kMaxWalRingBytes` | `64MB`（`64ull*1024*1024`） |
| `Options::wal_ring_bytes` | 0 = 默认 64KB；范围 `[4160B, 64MB]`；**仅首次布局**（`wal_ring_off==0`）生效，既有映像以 `SuperBlock.wal_ring_bytes` 为准并忽略本次配置 |
| `Config::wal_ring_kb` | rtdbd 配置项，范围 `64~65536`（64KB~64MB）；`server.cpp` 以 `wal_ring_bytes = wal_ring_kb << 10` 传入 |
| 分配策略 | ≤64KB 走 Slab；>64KB 走 `ReservePermanent` 永久区预留 |

创建后**不可在线改容**，换容量须新建映像。`HasRoomFor(rec_bytes)` 精确判据（P0-3 修复）
除总量外还校验回绕落位约束，防止垫片回绕后覆盖 `[tail_pos, head_pos)` 环内数据。

### 4.4 回绕、保留水位与快照不清环

- 记录尾部剩余 `< kWalMinRecordBytes(60B)`：不写内容直接回绕，扫描方一律跳过。
- 剩余 `≥60B` 但容不下当前记录：写一条 `kWalOpPad` 填充记录占满至区尾，再从头继续。
- **覆盖前先落盘**：环空间不足时写路径先 `FlushNow` 组刷全映像、推进
  `checkpoint_seq`，再 `ReclaimForRecord(rec_bytes, safe_through_seq)` **按需**从 tail
  起丢弃 `seq ≤ safe_through_seq` 的记录，只丢到"刚好够写"，保留尽量新的后缀供订阅
  游标继续增量；`tail_seq` 即保留水位，`position+1 < tail_seq` → `kCursorOverflow`
  （整表重取 + `ResetTo`，重复允许、不漏投）。
- **冷快照 `CreateSnapshot` 只推进 checkpoint/flushed，不主动清空 WAL 环**（P0-5），
  避免在线订阅者仅因抓快照被驱逐；环空间仍由写满时的按需回收管理。
- 追加失败/校验失败 → `MarkPoisoned()`（持久化于环头，跨进程/重启可见），引擎此后
  拒写保读 `kPoisoned=301`。
- `RewindHeadAfterReplay` 在恢复路径把写头精确回退到有效前缀末尾，杜绝
  "committed_seq 跳过从未 COMMIT 的 seq 区间"产生幻影变更交付。

### 4.5 尾垫片与零填充长度下溢修复（2026-11-07）

`WriteTailPadAndWrap()`（`wal_ring.cpp:132-154`）：pad 记录总长 = `remaining`，
载荷长 = `remaining - kWalMinRecordBytes`（`kWalMinRecordBytes` 已含 56B 头 + 4B CRC），
零填充必须恰为载荷长度。**旧实现多减了一次 `kWalRecCrcBytes`**：当
`remaining ∈ [60,63]` 时 `size_t` 下溢成巨大值 → `memset` 越界写崩溃，D2 双机
实测表现为 `0xC0000005 / VCRUNTIME140`。修复后：
```cpp
std::memset(dst + kWalRecHdrBytes, 0,
            static_cast<size_t>(remaining - kWalMinRecordBytes));   // 恰为载荷长度
const uint32_t crc = Crc32(dst, static_cast<size_t>(remaining) - kWalRecCrcBytes);
EncodeU32LE(dst + remaining - kWalRecCrcBytes, crc);
```
`[待实测]` 该边界（remaining 60~63B）需纳入混沌 100 轮与标准 CI 复核。

## 5. 网络帧协议 v1（`proto_v1.h` / `net/wire.hpp`）

### 5.1 20B 定长帧头

```
[0..3]   magic = 'R','T','D','B'      (0x52 0x54 0x44 0x42)
[4]      ver        u8 = RTDB_PROTO_VERSION(1)
[5]      flags      u8：bit0 = RTDB_PROTO_FLAG_RESP(0x01) 应答帧；bit1 压缩预留(v1 恒 0，不解压即拒绝)
[6..9]   session    u32（AUTH 前恒 0）
[10..11] func       u16
[12..15] payload_len u32
[16..19] crc        u32 IEEE CRC32
[20..]   payload
```
`RTDB_PROTO_HEADER_BYTES=20`；`RTDB_PROTO_MAX_PAYLOAD_BYTES=4*1024*1024`（4MiB）；
`RTDB_PROTO_MAX_NAME_BYTES=1024`；`RTDB_PROTO_MAX_BLOCK_COLS=64`；
`RTDB_PROTO_MAX_BLOCK_ROWS=1048576`；`RTDB_PROTO_DEFAULT_PORT=7878`。
**所有多字节整数显式小端编码**，与主机字节序无关。

- CRC = `Crc32(头 20B 且 crc 字段置 0 + 载荷)`；`DecodeFrameHeader` 校验 magic/版本/
  压缩位/载荷上限，违例 `kProtocolError=403`。
- 请求 `flags=0`，payload = 请求体；应答 `flags=RESP`，payload =
  `[i16 err]` + 成功体 / 失败时 `[u16 msg_len][UTF-8 描述]`（人读，客户端可忽略）。
- `Writer/Reader`（`net/codec.hpp`）：`Reader` 具**粘滞失败态**，越界即失效，
  载荷解析统一以 `Finish()`（ok 且恰读尽）做单一出口校验。

### 5.2 func 编号表（只增不改）

| func | 名称 | func | 名称 |
|---|---|---|---|
| 1 | `RTDB_PF_AUTH` | 20 | `RTDB_PF_SUBSCRIBE` |
| 2 | `RTDB_PF_PING` | 21 | `RTDB_PF_FETCH_DELTA` |
| 10 | `RTDB_PF_DDL` | 22 | `RTDB_PF_ACK` |
| 11 | `RTDB_PF_EXEC_BATCH` | 23 | `RTDB_PF_UNREGISTER` |
| 12 | `RTDB_PF_SCAN` | **40** | **`RTDB_PF_ADMIN`（M4 新增）** |
| 13 | `RTDB_PF_SCAN_PAGE` | **41** | **`RTDB_PF_AUTHZ_ME`（M4 新增）** |

**子码**：DDL `CREATE_TABLE=1 / DROP_TABLE=2 / DESCRIBE_TABLE=3`；
`ADMIN` 载荷首字节 `RTDB_ADMIN_STATS=1 / RTDB_ADMIN_AUTHZ_SHOW=2`；
`EXEC_BATCH` 模式 `MODE_OPS=0`（`ExecuteBatch` 操作表）/ `MODE_BLOCK=1`（`UpsertBatch`
列式块）；`SCAN_PAGE` `OPEN=0 / FETCH=1 / CLOSE=2`。

- **STATS 应答** = `[u16 ver=RTDB_STATS_VERSION(1)][u32 n][(u16 key)(u64 value)]*`；
  键 1~19 为服务端基座指标，20~35 为引擎侧 `Engine::Metrics()` 指标（D3，只增不改，
  逐项口径见 C4）。
- **AUTHZ_ME / AUTHZ_SHOW 应答** = `[Str user][u8 flags][u32 n_r][Str]*[u32 n_w][Str]*`；
  `flags`：`RTDB_AUTHZ_FLAG_ADMIN=0x01 / DDL=0x02 / **LEGACY=0x04**`。
- **AUTH 响应保持不变**（session id + ttl），保证 M3 客户端兼容。

### 5.3 值 / 行 / 块线编码（`net/value_codec.hpp`）

| 类别 | 常量 | 线格式 |
|---|---|---|
| 行式值标签 | `RTDB_VAL_NULL=0` | 空值（无载荷） |
| | `RTDB_VAL_I64=1` | `[i64]`（整数类/bool/时间戳统一 i64 承载） |
| | `RTDB_VAL_F64=2` | `[f64]`（浮点统一 f64，按位模式 `F64()`） |
| | `RTDB_VAL_VAR=3` | `[u32 len][bytes]` 变长列内容 |
| 块列载荷 | `RTDB_BLKPT_I64=0` | `[i64 × n_rows]` |
| | `RTDB_BLKPT_F64=1` | `[f64 × n_rows]` |
| | `RTDB_BLKPT_VAR=2` | `[u32 len][bytes] × n_rows` |
| 变更操作码 | `RTDB_CHG_INSERT=1 / UPDATE=2 / DELETE=3` | 与 WAL op 独立映射 |

行式值自描述（tag + 载荷），读取端按 schema 列类型做相容性校验；`WriteRow` 逐值编码
（长度由 schema 决定，不写入行内长度）；结果集头 `WriteResultHeader` 携带
表名 + 列（名/类型）+ 行数，客户端无需预先 Describe。列式块对齐 `RecordBlockView`
（i64/f64/var 三类载荷 + 逐列 `null_flags` 1B/行掩码）。

## 6. 错误码与兼容矩阵

### 6.1 协议常用错误码（`proto_v1.h` 的 `RTDB_E_*`，与 `err.hpp` 对齐）

`0 OK / 101 INVALID_ARGUMENT / 102 NOT_FOUND / 107 TIMEOUT / 303 TABLE_NOT_FOUND /
400 NOT_IMPLEMENTED / 401 NETWORK / 402 CURSOR_OVERFLOW / 403 PROTOCOL /
404 TOO_MANY_SESSIONS / 501 AUTH_FAILED / 502 TOKEN_EXPIRED /
**503 PERMISSION_DENIED（M4 追加）**`；另有 3xx 的 `RTDB_E_*` 未收录于本子集但
数值与 `Err` 一致（如 `kSqlSyntax=307` 仅 C++ 面）。完整表见 C2 §6。

### 6.2 兼容矩阵（D11）

| 场景 | 行为 | 依据 |
|---|---|---|
| **C ABI v2 只增符号** | v1 14 符号语义/签名不变；v2 订阅族 6 符号追加；`RTDB_ABI_VERSION == RTDB_ABI_VER == 2` 由 `static_assert` 单一真源保证 | `src/api/c_abi.cpp:27`、`test_compat.cpp:57-59` |
| **shm 布局** | `kShmFormatVersion` 保持 2（M4 不升级）；PerfCounters 走 host + RPC，避免布局升级 | `test_compat.cpp:60-61` |

| **M4 客户端 ↔ M3 服务端** | 新增 func `ADMIN=40 / AUTHZ_ME=41` 统一降级 `kNotImplemented=400`，保持连接与会话不崩溃；旧 func 不受影响 | `test_compat.cpp::NewFuncsDegradeToNotImplementedOnLegacyServer`（协议层模拟，真实 M3 二进制不可得） |

## 7. 版本纪律与升级路径

1. **协议 v1**：func/子码/标签/错误码数字只增不改；M4 只追加 `ADMIN=40`、
   `AUTHZ_ME=41`、`RTDB_E_PERMISSION_DENIED=503`、`kSqlSyntax=307`（C++ 面）与
   STATS 键 20~35、`RTDB_AUTHZ_FLAG_LEGACY=0x04`。
2. **C ABI v2 冻结**：M4 只使用/测试，不新增符号、不改既有签名；SQL C ABI 需 v3，归 M5。
   两处 `RTDB_ABI_VER` / `RTDB_ABI_VERSION` 任一漏改由 `static_assert` 在编译期暴露。
3. **shm 布局**：M4 不改 SuperBlock 稳定字段、不递增 `kShmFormatVersion`；任何未来
   破坏存量映像可读性的布局改动必须递增该值，并**在 `tools/migrate_from_psrtdb`
   中提供升级路径**（C5 §9 的 `IPsrImageAdapter` 可扩展为旧格式读取），同时
   同步 `RefreshLayoutCrc` 的稳定字段锚点。
4. **版本串**：M4 收口把 `kVersionString` 推进到 `0.2.0`，并把
   `RTDB_VERSION_MINOR` 同步为 `2`（**ABI 版本保持 2、shm 布局保持 2**，
   未引入破坏存量映像或 ABI 的变更）。docs/16 D11 原文「MINOR 0→1」为笔误
   （0.1.0 时 MINOR 已是 1），2026-11-09 已按语义版本修正并在 `version.hpp`
   注释留痕；打 `m4` tag 时按 §8 复核。
