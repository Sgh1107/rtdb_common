## 1. 混沌 100 轮（docs/05 §5 第 2 项）

```bash
RTDB_TEST_BIN=<build>/rtdb_unit_tests.exe \
RTDB_CHAOS_WORKDIR=<build>/chaos100 \
scripts/chaos_m4.sh 100
```

- 过滤器 `NetChaos.*`，`--gtest_repeat=100`；每轮由用例独立取回端口与映像，进程内拉起真实 rtdbd → 硬杀 → 重启 → 校验。
- 校验点：`Kill9RestartResumesDelivery`（无缺漏、交付 seq 严格递增、写者心跳前进）、`KillDuringWriteBurstSustainsDelivery`（`acked ⊆ 交付`）。
- **结果：100 轮 / 200 个用例 PASS，0 FAILED，耗时 16m42s**；脚本退出码 0。
- 原始日志：`chaos_m4_20261109_171144.log`。统计方式：`grep -c "[       OK ]"` = 200、`grep -c "[  FAILED  ]"` = 0。
- 注：本机 MinGW 在所有用例 PASSED 之后的进程退出清理阶段报 SEGFAULT(139)，为已知工具链现象（docs/16 §13.3）；脚本以 gtest 用例结果为准判定，其它非零退出码仍一律判失败。

## 3. C4 故障恢复演练（docs/05 §5 第 8 项）

```bash
RTDBD_BIN=<build>/rtdbd.exe RTDBCTL_BIN=<build>/rtdbctl.exe \
RTDB_DRILL_WORKDIR=<build>/opsdrill2 \
scripts/ops_drill.sh
```

链路：生成 `ops_drill.cfg`（`snapshot_on_exit=true`、口令摘要由 `rtdbd --hash-password` 生成）→ 启动 `rtdbd --exit-after-ms 15000` → `rtdbctl ddl create meters` → `import meters --file seed.csv`（3 行）→ `export` 基线 → **自动优雅退出抓快照** → 备份主映像与 `.snap` → 移走主映像（文件级模拟坏盘）→ 用 `.snap` 恢复 → 重开服务 → `export` 复验。

- **结果：PASS，耗时 31s**；基线/恢复后导出均为 4 行（含表头），`diff` 内容一致；原始日志 `ops_drill.log`。
- 关键经验：Windows Git Bash 下 `kill -INT` 对 native 进程不触发控制台优雅退出，实测不会生成 `.snap`；改用 `--exit-after-ms`（走 `srv.Stop()` → 排空会话 → `CreateSnapshot`）后通过。该口径已同步进 [C4 §6](../C4_运维手册.md)。
- 「坏盘」为文件级移走主映像，非真实磁盘故障；目标环境演练仍需另行留证。

## 4. `rtdbctl` 数据面端到端（随 §3 演练，docs/05 §5 第 6 项）

`ops_drill.sh` 链路中以下命令全部 `rc=0`：

```
rtdbctl ddl create meters --col id:int64 --col val:float64 --col name:utf8 [连接参数]
rtdbctl import meters --file seed.csv [连接参数]
rtdbctl export meters --file before.csv [连接参数]
rtdbctl export meters --file after.csv [连接参数]     # 恢复后
```

`import`(CSV 3 行) → `export`(4 行含表头) → 恢复后 `export` 与基线 `diff` 一致，验证 CSV 解析、批原子写、分页导出与转义链路。
**`rtdbctl subscribe` 端到端冒烟仍待补**（`status/ddl/authz me|show|check` 已有 CI 与双机实证）。

## 5. 迁移工具端到端冒烟（docs/05 §5 第 7 项）

```bash
migrate_from_psrtdb --make-fixture smoke_fixture.json
migrate_from_psrtdb --source smoke_fixture.json --mapping smoke_mapping.json \
                    --target smoke.rtdb --dry-run
migrate_from_psrtdb --source smoke_fixture.json --mapping smoke_mapping.json \
                    --target smoke.rtdb --size-mb 16 --batch 2 --report smoke_report.json
```

- dry-run：预估 3 行、不创建目标映像；正式迁移：`source_rows=3`、`target_rows=3`、`samples=3`、`sample_ok=true`、`key_checksum` 非零、`committed_seq/checkpoint_seq=8`、报告 `passed:true`，耗时 94ms。
- 单测：`MigrateTest` 8 例 + `Compat*` 4 例 = **12/12 PASS**（干净构建验证）；含新增 `NonFirstPrimaryKeyIsRejected`。
- 真实 PSRtdb 二进制映像不可得，fixture 适配器与报告 `note` 已明确记录该限制（docs/17 §6、C5 §9）。
