# C5 老系统迁移指南（PSRtdb → rtdb_common）

> 适用：`tools/migrate_from_psrtdb`（M4-W3，docs/16 D8/D10）。本文逐项对照
> **`tools/migrate_from_psrtdb/migrate_core.hpp` 与 `main.cpp` 的当前实现**，
> 所有字段、命令、算法、错误文案均取自代码与 `tests/unit/test_migrate.cpp`，
> 不臆造源格式。
>
> **最重要的一条已知限制**：**真实 PSRtdb 二进制映像格式不可得**。本版交付
> **自描述同构 fixture 适配器**（`FixtureAdapter`）作为默认源；报告的 `note`
> 字段会原样写出该限制，避免被误读为"已验证真实老格式"。接入真实老映像只需
> 实现 `IPsrImageAdapter`（§9），迁移/校验/报告链路无需改动。
>
> **标记约定**：`[待实测]` = 需真实老映像/标准 CI 复核；`[待评审]` = 需在 M4
> 收口评审确认的边界或接线项。

## 1. 工具定位与链路

核心逻辑全在 `migrate_core.hpp`（单测直接 `#include "tools/migrate_from_psrtdb/
migrate_core.hpp"`，不依赖 `main`）；`main.cpp` 仅做 CLI 参数解析与打印。
链路（`Run`，`migrate_core.hpp:504-688`）：

```
读 mapping.json → ParseMapping → FixtureAdapter.Tables()（源表/列/行）
  → 按表名索引源表 + 校验源列存在 → [dry-run 到此为止并写报告]
  → 拒绝覆盖已存在目标 → Engine::Open（按 wal_ring_bytes 预算建映像）
  → 逐表 CreateTable → 逐行类型转换/默认值 → 分批 ExecuteBatch
  → ScanAll 全表重读校验 → 抽样逐值比对 → CreateSnapshot → 写报告 JSON
```

共享内存布局与 C ABI 均不变；迁移只经 Engine 本地 API（`CreateTable /
ExecuteBatch / ScanAll / CreateSnapshot`），不引入新的持久化语义。

## 2. 概念 / 类型对照表

`TypeOf()`（`migrate_core.hpp:255-268`）把源列类型字符串映射到 `rtdb::DataType`
（`table_def.hpp`，只增不改）；`ts` 对应时间戳语义的定长 64 位整数。

| 源类型串 | `DataType` | 值 | 说明 |
|---|---|---|---|
| `int8` | `kInt8` | 1 | 8 位有符号 |
| `int16` | `kInt16` | 2 | 16 位有符号 |
| `int32` | `kInt32` | 3 | 32 位有符号 |
| `int64` | `kInt64` | 4 | 64 位有符号（主键常用） |
| `bool` | `kBool` | 7 | 1 字节 0/1 |
| `float32` | `kFloat32` | 5 | 32 位浮点 |
| `float64` | `kFloat64` | 6 | 64 位浮点 |
| `utf8` | `kUtf8Var` | 8 | 变长 UTF-8，内容在变长池 |
| `bytes` | `kBytesVar` | 9 | 变长二进制块 |
| `ts` | `kUnixTsNs` | 10 | Unix 纳秒时间戳（定长 i64） |

| PSRtdb 侧概念 | rtdb_common 侧落点 |
|---|---|
| 表 / 列定义 | `TableDef` / `ColumnDef`（`CreateTable`）；列 0 为整数类非空主键 |
| 行 | `vector<ColumnValue>`（顺序与建表列序一致） |
| 缺列默认值 | `mapping.json` 的 `defaults`（按目标列名给字符串默认值） |
| 时间戳单位 | 当前实现**按目标 `DataType` 重新标注**（`IntOf/Real/Bytes/Text`），未做单位换算；`ts` 直接作为 i64 承载。`[待评审]` 若老系统时间戳非纳秒需扩展转换规则 |
| 二级索引 | 本版 `Run` 的 `TableDef` 未设 `secondary`、未调用 `CreateSecondaryIndex`；mapping.json 无二级索引字段。`[待评审]` |
| 主键 | `TableMap::primary_key` 解析后写入 `TableDef::primary_key`；引擎 M2 口径要求主键恒为目标首列，非首列声明在零写入阶段报 `kInvalidArgument`；校验取每行 `row[0].as_int()` |

`ToValue()`（`migrate_core.hpp:270-292`）：JSON `null` → `ColumnValue::Null()`；
变长列要求 `kStr`；浮点列接受 `kNum` 或数字字符串（`strtod`）；整数类接受
`kNum`/`kBool`/数字字符串（`strtoll`），统一 `ColumnValue::IntOf(type, iv)`。

## 3. 自描述 fixture 格式（`--make-fixture`）

`MakeFixture()`（`migrate_core.hpp:713-734`）写出 `format: "rtdb_fixture_v1"` 的
JSON。根对象 `tables` 为数组，每表含 `name` / `columns` / `rows`；列含
`name` / `type` / 可选 `nullable`（默认 true）；每行是**与 columns 等宽**的值数组。
`FixtureAdapter::Tables()` 解析该结构：未知列类型报
`fixture: unknown column type X`，行宽不符报 `fixture: row width mismatch in table X`。

```json
{
  "format": "rtdb_fixture_v1",
  "tables": [
    {
      "name": "meters",
      "columns": [
        {"name": "id",  "type": "int64",   "nullable": false},
        {"name": "val", "type": "float64", "nullable": true},
        {"name": "name","type": "utf8",    "nullable": true}
      ],
      "rows": [
        [1, 1.5, "alpha"],
        [2, null, "beta"],
        [3, 3.5, null]
      ]
    }
  ]
}
```

## 4. mapping.json 完整示例与字段语义

`ParseMapping()`（`migrate_core.hpp:397-454`）。根对象 `tables` 数组；**未知源表 /
未知源列 / 未知类型一律明确报错，不静默跳过**。

```json
{
  "tables": [
    {
      "source": "meters", "target": "meters", "primary_key": "id",
      "columns": [
        {"source": "id",   "target": "id",   "type": "int64",   "nullable": false},
        {"source": "val",  "target": "val",  "type": "float64", "nullable": true},
        {"source": "name", "target": "name", "type": "utf8",    "nullable": true}
      ],
      "defaults": {"name": ""}
    }
  ]
}
```

| 字段 | 必填 | 语义 |
|---|---|---|
| `tables[].source` | 是 | 源表名，须在 fixture/源映像中存在；否则 `mapping: source table not in image: X` |
| `tables[].target` | 是 | 新映像中的表名（`CreateTable(def.name)`） |
| `tables[].primary_key` | 否 | 目标主键列名；缺省取 `columns[0].target`。`Run` 会写入 `TableDef::primary_key`；引擎要求主键为目标首列，指向其它列时在零写入阶段明确拒绝 |
| `tables[].columns[]` | 是（非空） | 列映射数组；`source` = 源列名，`target` = 目标列名，`type` ∈ §2 十种，`nullable` 缺省 true |
| `tables[].defaults` | 否 | 以**目标列名**为键的字符串默认值；源值为 NULL 时经 `ToValue` 按目标类型转换填充。仅当 JSON 值为 `kStr` 时生效（`has_default=true`） |

转换顺序（`Run` 逐行，`:594-627`）：取源值 → 若 NULL 且 `has_default` 用默认值
→ 若仍 NULL 且 `!nullable` 报 `NOT NULL column has NULL value: X` → 非 NULL 按目标
类型重新标注（浮点 → `Real`，变长 → `Bytes/Text`，其余 → `IntOf(cm.type, as_int())`）。

## 5. CLI 全流程（`main.cpp`）

```
migrate_from_psrtdb --source <fixture> --mapping <json> --target <image>
                    [--dry-run] [--limit N] [--batch N] [--size-mb N] [--report <json>]
migrate_from_psrtdb --make-fixture <path>
migrate_from_psrtdb --help | -h
```

| 参数 | 默认 | 语义 |
|---|---|---|
| `--source` | 必填 | 源 fixture 路径 |
| `--mapping` | 必填 | mapping.json 路径 |
| `--target` | 非 dry-run 必填 | 新映像路径（**必须不存在**） |
| `--dry-run` | false | 只解析 mapping/fixture 并预估行数，不创建目标映像、不写库；仍写报告 |
| `--limit N` | 0 = 不限 | 每表最多迁移 N 行（截断 `source_rows`） |
| `--batch N` | `512` | 原子批行数（`MigrateParams::batch_rows`；`0` 亦回落 512） |
| `--size-mb N` | `256` | 新建目标映像大小（`initial_size_bytes = N << 20`；`0` 回落 256） |
| `--report` | 空 = stdout | 报告 JSON 文件路径；由 `Run` 写盘（CLI 与单测共用同一路径） |
| `--make-fixture` | — | 生成 §3 样例 fixture 后直接退出 |

**退出码**：`0` = 成功（报告 `passed=true`）；`1` = 迁移/校验/IO 失败；
`2` = 用法错误（未知参数或缺少必填）。目标映像固定按
`instance="migrate_from_psrtdb"`、`role=Standalone`、`wal_fsync=PerSecond`、
`wal_ring_bytes=1<<20`（1MB 环预算）打开（`:558-567`）；
`max_rows_hint = source_rows + 64`。

端到端顺序（同 `test_migrate.cpp` 冒烟）：

```bash
migrate_from_psrtdb --make-fixture psr.fixture
migrate_from_psrtdb --source psr.fixture --mapping mapping.json \
                    --target new.rtdb --dry-run --report dry.json
migrate_from_psrtdb --source psr.fixture --mapping mapping.json \
                    --target new.rtdb --batch 256 --report report.json
```

## 6. 报告字段（`ReportJson`，`migrate_core.hpp:690-711`）

```json
{"passed":true,"dry_run":false,"elapsed_ms":12,"committed_seq":3,
 "checkpoint_seq":3,"note":"源映像格式：自描述 fixture（真实 PSRtdb 二进制格式不可得，适配器接口可替换）",
 "tables":[{"table":"meters","source_rows":3,"target_rows":3,
             "key_checksum":12638187200555641996,"samples":3,"sample_ok":true}]}
```

| 字段 | 语义 |
|---|---|
| `passed` | 全部分表校验通过且快照成功才置 true；失败时 Run 返回非 `kOk`、报告可能不落盘 |
| `dry_run` | 是否仅预估（此时 `target_rows=0`、不创建目标映像） |
| `elapsed_ms` | `steady_clock` 全程耗时 |
| `committed_seq` / `checkpoint_seq` | 迁移结束 `CreateSnapshot()` 后的引擎水位（dry-run 时为 `-1`） |
| `note` | 固定文案，明确真实 PSRtdb 二进制格式不可得、适配器接口可替换 |
| `tables[].table` | 目标表名 |
| `tables[].source_rows` | 源表行数（受 `--limit` 截断） |
| `tables[].target_rows` | `ScanAll` 重读到的行数；与 `source_rows` 不等即 `kCorruption` |
| `tables[].key_checksum` | 主键集合校验和（§7 算法） |
| `tables[].samples` / `sample_ok` | 抽样条数 / 逐值比对是否全一致 |

> `test_migrate.cpp:122` 断言 `note` 含 `"fixture"`；`ReportJson` 的 `key_checksum`
> 为 `uint64` 十进制文本，示例值仅示意（随数据变化）。`[待实测]` 示例数值需按
> 实际 fixture 重跑替换。

## 7. 抽样比对与主键校验和算法

全表重读 `ScanAll(table)` → `rows`（按主键升序）：

1. **主键集合校验和**（`migrate_core.hpp` 的 `Run` 校验段）：取每行 `row[0].as_int()`
   得 `keys`，`std::sort` 升序后做 **FNV-1a 64 位**：
   ```
   uint64_t sum = 1469598103934665603ull;          // FNV offset basis
   for (int64_t k : keys) { sum ^= (uint64_t)k; sum *= 1099511628211ull; }  // FNV prime
   ```
   与顺序无关（先排序）。`Run` 会对源侧 `converted` 的主键集合按**同一算法独立计算**
   并交叉比对，不一致返回 `kCorruption`（"primary key checksum mismatch"），
   避免"行数相同但主键被改写/错位"漏检；比通过后把目标侧值写入报告 `key_checksum`。
2. **抽样逐值比对**：`samples = min(5, rows.size())`，对前 N 行逐列
   `SameValue(rows[i][c], converted[i][c])`；`SameValue` 对 NULL 要求双方皆 NULL，
   浮点比 `as_real()`，变长比 `as_bytes()`，其余比 `as_int()`。
   任一行宽不符或值不符 → `sample_ok=false`。
3. **总判定**：`target_rows != source_rows || !sample_ok` →
   `Fail(kCorruption, "verification failed for table X")`；主键校验和不一致亦为 `kCorruption`。

> 抽样只覆盖前 5 行，**非全量逐值比对**；`key_checksum` 覆盖全体主键集合且已与源侧交叉比对。
> `[待评审]` 是否把抽样升格为全量逐值比对（M5 增强）。

## 8. 失败与回滚

| 情形 | 行为 |
|---|---|
| 目标映像已存在 | `ifstream` 探测到即 `Fail(kAlreadyExists, "target image already exists, remove it first: X")`，**绝不静默覆盖既有数据**（`test_migrate.cpp::ExistingTargetIsNeverOverwritten`） |
| `--dry-run` | 在写库前返回，不创建目标映像；但仍会写报告 |
| mapping/fixture 校验失败 | 在 `Engine::Open` 之前返回，**零写入** |
| 单批 `ExecuteBatch` 失败 | `Fail(..., "batch write X: ...")` 立即返回；**前面已提交的批次不会回滚** |

**分批无法全局原子的边界**（与 `rtdbctl import` 同一已知边界，见
`tools/rtdbctl/main.cpp:1165-1168`）：迁移按 `--batch` 逐批 `ExecuteBatch`，
每批自身原子（WAL 三段式），但**批间无全局事务**。若第 k 批失败，前 k-1 批已成为
目标映像中的前缀数据；`Run` 当前只返回错误码与简短文案，**不报告已写入的前缀行数、
也不删除半成品目标映像**。

处置建议（操作口径，非工具已实现行为）：

- 失败后不要复用该 `--target`；删除/改名半成品映像后，用**全新的目标路径**重跑。
- 如需确认前缀写入范围，用 `rtdbctl export <table>`（`ScanPaged` 分页导出，
  CSV/JSON）核对已落盘行，再决定重跑或补数；`rtdbctl import` 失败时会明确报告
  "已写入 N 行 / M 批"并提示以 export 核对，迁移工具可参考该口径增强。`[待评审]`
- 大表先 `--dry-run` 预估行数，再以较小 `--size-mb`/`--batch` 试跑，确认
  `wal_ring_bytes=1MB` 环预算足够容纳单批 WAL。

## 9. 真实 PSRtdb 二进制格式不可得的限制与 `IPsrImageAdapter` 接入

```cpp
// migrate_core.hpp:305-310
class IPsrImageAdapter {
public:
    virtual ~IPsrImageAdapter() = default;
    virtual bool Tables(std::vector<SrcTable>* out, std::string* err) = 0;
};
```
`SrcTable{ name, vector<SrcColumn> columns, vector<vector<ColumnValue>> rows }`；
`SrcColumn{ name, DataType type, bool nullable }`。`Run()` 当前**硬编码**
`FixtureAdapter adapter(p.source)`（`:515`）。接入真实老映像的步骤：

1. 实现 `IPsrImageAdapter::Tables()`：打开 PSRtdb 老映像、列举表/列定义、
   以行游标把每行转成 `vector<ColumnValue>`（按 `SrcColumn.type` 标注）；
   失败置 `err` 并返回 false。
2. 在 `Run()` 把 `FixtureAdapter` 替换/按 `--source` 后缀或新参数选择真实适配器
   （当前仅一处硬编码，接线点集中）。`[待评审]` 需评审是否新增 CLI 选择参数。
3. 其余链路（mapping 校验、类型转换、`ExecuteBatch`、校验报告、`CreateSnapshot`）
   **无需改动**；`note` 文案须随之更新，避免仍宣称"fixture 格式"。
4. 真实格式接入后，docs/16 §2.2 的"迁移示例老映像并抽样比对"验收才具备真实证据；
   现阶段验收以 fixture + 抽样比对为准（`docs/16 §13.4`）。`[待实测]`

## 10. 迁移后校验清单与常见错误

### 10.1 校验清单

- [ ] 报告 `passed=true`、`dry_run=false`、`tables[].source_rows == target_rows`、
      `sample_ok=true`、`samples>0`（`test_migrate.cpp:113-122`）。
- [ ] `committed_seq >= 1`、`checkpoint_seq` 已推进（`CreateSnapshot` 成功）。
- [ ] `note` 仍含 fixture 限制字样（真实格式接入前）。
- [ ] 目标映像可**独立重开**：`Engine::Open` → `OpenTable` → `ScanAll` 行数与
      抽样值一致（`:130-145`）；NULL 列按 `defaults` 转为空串（如 `name`）。
- [ ] 用 `rtdbctl export` 或 `rtdbctl status` 复核水位与行数；必要时跑 SQL
      `SELECT count(*)` 子集外不可用，改走 `ScanAll` 计数。
- [ ] 保留报告 JSON、dry-run 报告、mapping.json 与 fixture 作为验收证据。

### 10.2 常见错误与诊断

| 现象/文案 | 原因 | 错误码 |
|---|---|---|
| `mapping: unknown source column meters.nope` | mapping 的 `source` 列不在源表列定义中（`:530-532`） | `kInvalidArgument` |
| `mapping: unknown column type uuid` | `type` 不在 §2 十种字符串内（`:435-437`） | `kInvalidArgument` |
| `NOT NULL column has NULL value: id` | 源值为 NULL、`nullable=false` 且无 `defaults`（`:607-609`） | `kInvalidArgument` |
| `malformed JSON at offset N` / `trailing characters at offset N` | `Json::Fail`（`:71-74`）带**字符偏移** `pos_`，便于定位 fixture/mapping 的破损位置；常见为缺引号/多逗号/尾部垃圾 | `kInvalidArgument` |
| `fixture: missing tables array` / `fixture: malformed table entry` / `fixture: row width mismatch in table X` | fixture 结构或行宽不符（`:323-360`） | `kInvalidArgument` |
| `mapping: source table not in image: X` | `source` 表名在源映像中不存在（`:523-525`） | `kNotFound` |
| `target image already exists, remove it first: X` | 目标路径已存在（§8） | `kAlreadyExists` |
| `verification failed for table X` | 行数不等或抽样值不符（`:672-673`） | `kCorruption` |
| `open target: ...` / `create table X: ...` / `batch write X: ...` / `snapshot: ...` | 引擎侧错误透传 `ErrorMessage`（`:566/589/644/678`） | 原 `Err` |

CLI 失败统一打印 `迁移失败（<ErrorMessage>）：<err 文案>` 并返回 `1`
（`main.cpp:84-87`）；`err` 文案由 `Fail()` 填充，`malformed JSON` 类含偏移。
