# C1 安装部署指南

> 文档定位：面向部署/运维人员，说明从源码构建产物、以「嵌入形态」或「服务形态」落地、配置映像/网络/权限、升级回滚。对应 docs/16 D10（C1）。命令为可复现模板，路径与口令用占位符。
> **数值口径**：本文不产生实测值。出现的性能数字均引用既有实测并注明出处（docs/14 §6.2 的 211,558 行/s、docs/14 §5.1 的跨机 103,351 行/s），仅作容量语境，不作部署承诺。标注「模板/未实测」「待实测/待评审」的内容须在用户环境实操留证后方可作为基线。

## 1. 两种交付形态

| 形态 | 载体 | 使用方 | 运维关注点 |
|---|---|---|---|
| 嵌入形态 | `Engine` C++ API / `rtdb_cabi.h` C ABI，链接 `rtdbcore`，应用进程内打开映像 | 单进程直读、自研集成 | 映像权限、单写者、C ABI 版本、崩溃重放；无网络端口 |
| 服务形态 | 独立进程 `rtdbd`，TCP 协议 v1 对外提供 AUTH/DDL/EXEC_BATCH/SCAN/SUBSCRIBE | 多客户端、跨机、`rtdbctl`/`bench_net`/`remote_demo` | 监听与防火墙 5599/TCP、会话/超时、口令摘要、升级回滚 |

两形态共享引擎与映像格式（`kShmFormatVersion = 2`，`include/rtdb/version.hpp`），但**同一映像文件同一时刻只允许一个写者进程**（docs/15 §3：A 机唯一服务端，B 机只做客户端，不要用 B 直接打开 A 的映像）。服务形态下 rtdbd 即唯一写者。C ABI 当前 **v2**（`RTDB_ABI_VERSION = 2`，M3 订阅/会话符号集，与 `rtdb_cabi.h` 的 `RTDB_ABI_VER` 一致，`src/api/c_abi.cpp` 有 `static_assert` 编译期校验），主版本不变即可沿用既有嵌入集成方（§9）。

## 2. 环境依赖

| 平台 | 编译器/构建 | 其它 |
|---|---|---|
| Windows | VS 2019/2022/2026（C++ 桌面工作负载）+ Windows SDK，CMake ≥ 3.16 | MSVC 需 `/utf-8`（CMakeLists 已内置），无需固定生成器 |
| Linux | `build-essential`（或 `gcc-c++ make`）、CMake ≥ 3.16 | **必须装内核头**：Ubuntu/Debian `linux-libc-dev`，RHEL 系 `kernel-headers`（`<linux/futex.h>`，docs/18 §环境表） |

内核库零第三方依赖；仅单元测试在 `RTDB_BUILD_TESTS=ON` 时经 FetchContent 拉 GoogleTest（CMakeLists 头部注释）。离线按 §3.3 关测试即免联网。

## 3. 双平台构建

### 3.1 Windows（VS 2019/2022/2026）

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release --parallel
```
不写 `-G "Visual Studio 17 2022"`：docs/18 §环境表与 CI 注释要求 CMake **自动探测** VS 版本（windows-latest 默认 VS 2026，固定生成器会报找不到实例）。`-A x64` 指定 64 位，`--config Release` 在构建阶段指定。产物：`build\Release\rtdbd.exe`（服务主程序）、`build\Release\bench_net.exe`、`build\bin\Release\remote_demo.exe`。Windows 无 RPATH，CMake 已把 `rtdbcore.dll`/`rtdbclient.dll` 拷到 `build\bin\Release`；手工拷 exe 须连同 DLL，否则报 `0xC0000135`（docs/18 §排障表）。

### 3.2 Linux

```bash
sudo apt update && sudo apt install -y build-essential cmake linux-libc-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```
单配置生成器用 `-DCMAKE_BUILD_TYPE=Release`（配置阶段）。产物：`build/rtdbd`、`build/bench_net`、`build/bin/remote_demo`。RHEL 系把 `linux-libc-dev` 换 `kernel-headers`，缺则报 `linux/futex.h: No such file or directory`（docs/18 §排障表）。

### 3.3 离线最小构建（免 GoogleTest / 免联网）

```powershell
cmake -S . -B build -A x64 -DRTDB_BUILD_TESTS=OFF                      # Windows
cmake --build build --config Release --parallel
```
```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DRTDB_BUILD_TESTS=OFF  # Linux
cmake --build build --parallel
```
`-DRTDB_BUILD_TESTS=OFF` 必须放**配置阶段**（`cmake -S`）；`cmake --build` 不接受 `-D`。关闭后不引入 GoogleTest、不触发 FetchContent，适合生产机/内网离线构建（docs/18 §构建）。

## 4. CMake 构建开关速查

来源 `CMakeLists.txt` 顶部 `option(...)`。

| 开关 | 默认 | 作用 |
|---|---|---|
| `RTDB_BUILD_TESTS` | ON | 单元测试（GoogleTest 驱动）；**OFF = 免 GoogleTest / 免联网** |
| `RTDB_FETCH_GTEST` | ON | 仅 `RTDB_BUILD_TESTS=ON` 且未定义 `RTDB_GTEST_READY` 时生效，配置期拉 GoogleTest |
| `RTDB_BUILD_SQL` | ON | 内嵌 SQL 子集；OFF 时整体裁剪 `ExecuteSql`（docs/16 D5/D6/D7） |
| `RTDB_BUILD_TOOLS` | ON | `bench_net`、`rtdbctl` 等工具 |
| `RTDB_BUILD_EXAMPLES` | ON | `remote_demo` 等示例（输出到 `build/bin`） |
| `RTDB_BUILD_FUZZER` | OFF | libFuzzer 目标（Clang/GCC，手动） |
| `RTDB_BUILD_DIAG` | OFF | 本地诊断 repro |

生产建议 `-DRTDB_BUILD_TESTS=OFF`，按需叠加 `-DRTDB_BUILD_TOOLS=OFF -DRTDB_BUILD_EXAMPLES=OFF -DRTDB_BUILD_SQL=OFF`。**运维机须保留 `RTDB_BUILD_TOOLS=ON`**（`rtdbctl` 在 tools 内）。

## 5. 目录、权限与磁盘

- **映像必须放本地磁盘**：不要放 SMB / NFS / 网络盘 / UNC。依据 docs/18 §环境表「映像必须放本地磁盘，不要放 SMB/网络盘/UNC（`FlushFileBuffers` 语义）」——持久化依赖 mmap 文件背衬与刷盘语义，网络文件系统缓存/锁行为不满足该假设。
- **父目录先建且可写**：`path` 必填，首次启动只自动建映像文件、**不自动建父目录**；否则报「启动失败：io error」（docs/18 §配置与排障）。
- **空间**：默认 `size_mb = 256`，建议预留 ≥ 1 GB 本地空闲（docs/18 §环境表），另为 `.snap` 快照副本预留整映像空间（§9）。
- **单写者**：同一 `path` 只由 rtdbd 一个写侧进程打开，多进程同写属未定义行为（`include/rtdb/options.hpp` `Role::Standalone` 注释）。
- **账号**：服务进程只需对映像目录可读写，不需管理员/root；绑 5599 与注册系统服务（§10）需相应特权。Windows 目录被设 Low IL 会写失败，排查见 docs/18 §排障表。

## 6. 网络与防火墙（5599/TCP）

rtdbd 默认**仅绑回环** `127.0.0.1:5599`（安全默认，`src/server/config.hpp`），对外须显式放开（§7.3）。`include/rtdb/proto_v1.h` 的 `RTDB_PROTO_DEFAULT_PORT = 7878` 只是协议默认字面量，docs/14/15/18 执行单统一用 5599，以配置为准。

Windows（管理员 PowerShell，docs/14 §8.2、docs/15 §5.4）：
```powershell
netsh advfirewall firewall add rule name="rtdb 5599" dir=in action=allow protocol=TCP localport=5599
netsh advfirewall firewall add rule name="rtdb 5599 from B" dir=in action=allow protocol=TCP localport=5599 remoteip=<B-IP>
netsh advfirewall firewall delete rule name="rtdb 5599 from B"
```
Linux（ufw，docs/14 §8.2、docs/15 §5.4）：
```bash
sudo ufw allow 5599/tcp
sudo ufw allow from <B-IP> to any port 5599 proto tcp
sudo ufw delete allow from <B-IP> to any port 5599 proto tcp
```
firewalld（**模板/未实测**，RHEL 系写法，需用户环境验证）：
```bash
sudo firewall-cmd --add-port=5599/tcp --permanent && sudo firewall-cmd --reload
sudo firewall-cmd --query-port=5599/tcp
```
预检：B 机 `nc -zv <A-IP> 5599` / `Test-NetConnection <A-IP> -Port 5599`；服务端 `netstat -ano | findstr :5599` / `ss -ltnp | grep 5599`。跨机演示建议在受信内网执行，验证结束关闭端口（docs/14 §8.2）。

## 7. 首次启动与配置

### 7.1 CLI 全貌（`src/server/main.cpp` `PrintUsage()`）

```
rtdbd --config <cfg> [--listen HOST:PORT] [--path IMG] [--instance NAME]
      [--auth-salt SALT] [--user NAME=64HEX[#PERM]]... [--exit-after-ms N] [--log-denied]
rtdbd --hash-password PASSWORD [--salt SALT]
```
CLI 优先级高于配置文件：`--listen`/`--path`/`--instance`/`--auth-salt`/`--user` 覆盖 `cfg` 字段，`--log-denied` 在其它覆盖后写入 `cfg.log_denied`。

### 7.2 口令摘要：三处 salt 必须一致

摘要 = `SHA-256(auth_salt || password)`（`src/server/config.hpp`），离线生成：`rtdbd --hash-password <口令> --salt <盐>` 输出 64 位十六进制。**三处 salt 一致**是 AUTH 成功前提，任一处不一致返回 501：① 生成摘要时的 `--salt`；② rtdbd 配置 `auth_salt = <盐>` 或 `--auth-salt`；③ 客户端 `rtdbctl --salt` / `bench_net --salt` / `remote_demo` 的盐。配置每用户一行 `user = <name> <64hex> [perm]`；`perm` 空 = M3 兼容 admin（docs/16 D1），显式可写 `admin`/`ddl`/`r:<tables>`/`w:<tables>`/`rw:<tables>`；CLI 等价 `--user NAME=64HEX[#PERM]`。盐与摘要非机密，按部署统一分发；轮换需重启 rtdbd 并同步客户端（docs/14 §8.3）。**用户表为空则拒绝全部 AUTH（501）**，首次部署至少配一条 `user`。

### 7.3 `--listen 0.0.0.0:5599` 必须显式放开

```powershell
.\rtdbd.exe --config .\rtdb.cfg --listen 0.0.0.0:5599
```
不写 `--listen`（配置也无 `listen`）时只监听 `127.0.0.1:5599`，跨机连不上（docs/14 §5.1 注意事项、§8.1）。也可在配置写 `listen = 0.0.0.0:5599`；CLI 同名参数再次覆盖。`ParseListen` 支持 `[v6]:port`，端口必填、允许 0（`src/server/config.cpp`）。

### 7.4 配置文件示例（`rtdbd --config`）

`rtdb.cfg`（ASCII/UTF-8，`#` 注释，**未知键被拒绝**，`ParseConfigText`）：
```ini
instance = prod
path = D:/rtdb/prod.rtdb          # 父目录须先存在、本地磁盘、可写
size_mb = 256
wal_ring_kb = 0
listen = 0.0.0.0:5599            # 默认仅回环；对外必须显式
fsync = per_second
auth_salt = <部署共享盐>
user = ops <--hash-password 的 64 位输出> admin
user = viewer <另一条 64hex> r:*
session_ttl_ms = 1800000
max_sessions = 64
handshake_timeout_ms = 10000
idle_timeout_ms = 300000
max_auth_failures = 5
auth_backoff_ms = 200
max_payload_kb = 4096
heartbeat_ms = 1000
max_delta_kb = 1024
delta_max_timeout_ms = 25000
snapshot_on_exit = false
```

### 7.5 配置项与合法范围速查

字段名/默认值来自 `src/server/config.hpp`，范围来自 `src/server/config.cpp` `ParseConfigText`（越界即 `kInvalidArgument`，启动失败）。

| 配置键 | 默认 | 合法范围 | 说明 |
|---|---|---|---|
| `instance` | `rtdbd` | 非空 | 实例名/日志标识 |
| `path` | 必填 | 非空 | 映像路径；不自动建父目录 |
| `listen` | `127.0.0.1:5599` | `host:port` / `[v6]:port` | 默认仅回环 |
| `size_mb` | 256 | 1 ~ 4096 | 新建映像大小（MB）；已存在文件忽略 |
| `wal_ring_kb` | 0 | 0 或 64 ~ 65536 | WAL 环容量（KB）；0 = 引擎默认 64KB；仅新建生效 |
| `fsync` | `per_second` | `never`/`per_second`/`always` | 三档持久化，见 C4 §1.1 |
| `auth_salt` | 空 | 字符串 | 部署共享盐 |
| `user` | 空 | `name 64hex [perm]` | 空 = 拒绝全部 AUTH |
| `session_ttl_ms` | 1800000 | 1 ~ 86400000 | 会话 TTL，滚动续期 |
| `max_sessions` | 64 | 1 ~ 1024 | 并发会话上限（404） |
| `handshake_timeout_ms` | 10000 | 0 ~ 3600000 | 未认证握手窗口 |
| `idle_timeout_ms` | 300000 | 0 ~ 86400000 | 已认证空闲上限，0 = 不限 |
| `max_auth_failures` | 5 | 1 ~ 1000 | 单连接失败上限，达到即断连 |
| `auth_backoff_ms` | 200 | 0 ~ 60000 | 线性退避基数（ms） |
| `max_payload_kb` | 4096 | 1 ~ 65536 | 帧载荷上限（默认 4 MiB） |
| `heartbeat_ms` | 1000 | 1 ~ 60000 | 写者心跳周期 |
| `snapshot_on_exit` | false | true/false/1/0/on/off/yes/no | 优雅退出抓冷快照 |
| `max_delta_kb` | 1024 | 1 ~ 65536 | FETCH_DELTA 响应体上限（默认 1 MiB） |
| `delta_max_timeout_ms` | 25000 | 1 ~ 3600000 | FETCH_DELTA 长轮询上限 |

`--log-denied` **只有 CLI 开关、无配置键**（`main.cpp` 直接写 `cfg.log_denied`），见 C4 §4。

## 8. 容量规划：`size_mb` 与 `wal_ring_kb`

`size_mb`（1~4096，默认 256，对应 `Options::initial_size_bytes`）：含头部，**仅新建映像生效**，已存在文件忽略（`include/rtdb/options.hpp`）。`wal_ring_kb`（0 或 64~65536，即 64KB~64MB，底层 `Options::wal_ring_bytes` 允许 `[4160B, 64MB]` 约 `[4KB, 64MB]` 含 64B 环头）：**只在环首次布局（`SuperBlock.wal_ring_off == 0`）生效**，既有映像以 `SuperBlock.wal_ring_bytes` 为准，改配置不改变旧映像的环（docs/03 §3.2、docs/14 §11.4、docs/15 §5.2）。增大环可降低高频写+订阅断线的溢出（402）重取频率，代价是常驻空间增加，>64KB 由分配器**永久区预留**切出、生命周期内不归还（docs/03 §3.2、docs/14 §8.4）。默认 64KB 环下 3×int64 表单批 ≤512 行安全、768 行即 306（引用 docs/14 §6.3 既有实测，非本文标定），环可配后单批上限随容量线性提升。

容量语境（均引用既有实测）：本机回环 **211,558 行/s**（docs/14 §6.2）；跨机（桥接虚拟网络 + A 机 100 Mbps 物理链路）中位 **103,351 行/s**（docs/14 §5.1），按方案 A 记为已知限制，200k 为裸机千兆理想目标、性能专项归 M5（docs/14 §5.2）。**不得把回环基线与跨机数据混记**作为部署验收值（docs/14 §5.2 备注）。

## 9. 升级与回滚

**兼容前提**：C ABI 保持 v2（`RTDB_ABI_VERSION = 2`，嵌入方按 `RTDB_ABI_VER` 校验，主版本不变即可替换二进制）；共享内存布局 `kShmFormatVersion = 2`，破坏存量映像可读性的改动会递增该值并在迁移工具提供升级路径（`include/rtdb/version.hpp`）；既有映像 WAL 环以 SuperBlock 为准，升级不要指望改 `wal_ring_kb` 重设旧环，要换容量须新建映像+迁移。

**备份（升级前必做）**：① 停服（优雅 `Ctrl+C`/SIGINT，勿 `kill -9`，避免留下需重放的 WAL 窗口）；② 需冷快照则部署前置 `snapshot_on_exit = true` 或嵌入侧调 `Engine::CreateSnapshot()` 生成 `<映像>.snap`——「停写 → 全映像 flush → checkpoint 推进 → 整体拷贝」的一致性点副本，**整体拷贝而非 rename、本身是完整映像可独立挂载恢复**（`include/rtdb/engine.hpp` CreateSnapshot 注释）；③ 把映像与 `.snap` 复制到备份目录（留时间戳），记录 `size_mb`/`wal_ring_kb`/`fsync` 与二进制版本。

**升级**：替换新二进制（含 DLL/嵌入库），保持配置与 `path` 不变 → 先 `--exit-after-ms` 短时拉起冒烟（退出码 0），确认能打开既有映像、`rtdbctl status` 可读、`export` 可抽样 → 按 §10 正式拉起。

**回滚**：停新 → 恢复旧二进制 → 用映像备份（或 `.snap` 去后缀副本）覆盖回 `path` → 旧版本重开；若升级期间有新写入需回退，优先用升级前一致性快照恢复，避免新旧 WAL 混放。重开后引擎既有恢复路径重放 `(checkpoint_seq, 尾]` 收敛（docs/03 §3.3）。以上为**口径模板**，步骤与耗时需用户环境实操留证（docs/16 §8）。

## 10. 以服务方式运行（模板/未实测）

以下均标注「**模板/未实测**」：本仓未随附已验证的 unit/服务脚本，路径、账号、工作目录须按用户环境调整并实操留证后方可作为基线。

### 10.1 Linux systemd unit（模板/未实测）
```ini
# /etc/systemd/system/rtdbd.service
[Unit]
Description=rtdb_common rtdbd
After=network.target
[Service]
Type=simple
User=rtdb
WorkingDirectory=/opt/rtdb
ExecStart=/opt/rtdb/bin/rtdbd --config /etc/rtdb/rtdb.cfg --listen 0.0.0.0:5599
Restart=on-failure
KillSignal=SIGTERM
TimeoutStopSec=30
[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload && sudo systemctl enable --now rtdbd && sudo systemctl status rtdbd
```
要点：`User=rtdb` 须对 `path` 目录可读写；`ExecStart` 用绝对路径；`KillSignal=SIGTERM` 配合 `snapshot_on_exit` 决定退出是否抓快照。

### 10.2 Windows 服务注册要点（模板/未实测）

`rtdbd` 本体是控制台进程（控制台事件/SIGINT 触发优雅退出），**未内置 Windows 服务 SCM 入口**；常见做法是借助服务包装器（NSSM/srvany 等）托管 `rtdbd.exe --config ... --listen 0.0.0.0:5599`：
```powershell
sc.exe create rtdbd binPath= "<包装器> --config D:\rtdb\rtdb.cfg --listen 0.0.0.0:5599" start= auto
sc.exe start rtdbd && sc.exe query rtdbd && sc.exe stop rtdbd
```
要点：服务账号须对映像目录有写权限；包装器须把停止信号转成 Ctrl+C/SIGTERM 以触发 `srv.Stop()` 优雅退出，否则可能跳过 `snapshot_on_exit`；`--listen` 与防火墙规则（§6）须同时配置。

## 11. 安全边界

协议为**明文 TCP + 摘要口令**（`SHA-256(盐‖口令)`），**不是 TLS**；仅限受信内网，公网暴露须自行加隧道/网关，TLS 归 M5 评估（docs/14 §8.3、docs/16 §3）。rtdbd 默认只绑回环，对外监听须显式 `--listen`/`listen` 并配合 `max_sessions` 会话上限与防火墙白名单（docs/14 §8.3）。盐与摘要按部署分发管理，轮换需重启并同步客户端。口令与摘要不构成机密，但不要把 admin 账号随意下发；表级权限门与 `--log-denied` 审计见 C4 §3/§4。
